# 09 變現與廣告政策

> 版本：1.1 ｜ 更新日期：2026-11-05 ｜ 適用：所有 SEO 網站專案 ｜ 撰寫：Claude（1.1：AdSense 細節移至 22 章）

## 本章摘要

1. AdSense 的申請、政策、版位、無效流量與問題排解以 22 章為準（本章 §1、§2、§3、§8 只留摘要）：沒有流量門檻，審核看「原創、有價值、可導覽、政策合規」，最常見拒絕原因是 Low value content 與內容不足（詳見 22 §1、§6）。
2. 高階聯播網門檻 2025–2026 大幅變動：Journey by Mediavine 降到 1,000 個 premium sessions（截至 2026-08 官方公告）、Raptive 降到 25,000 pageviews（2025-10-16）、Ezoic 反而升到 250,000 月活躍使用者（2026-02-19）；Tier 1 流量要求因平台而異：Journey 看 premium sessions 的絕對數量且其他國家流量不扣分、Raptive 看比例（25k–99,999 需 ≥ 50%，100k+ 需 ≥ 40%）、Mediavine 看年廣告收入，東南亞流量站要逐平台判斷（https://www.mediavine.com/blog/two-years-of-journey-by-mediavine/ 、https://help.raptive.com/hc/en-us/articles/360032840891-Who-is-eligible-for-Raptive）。
3. RPM 的決定順序：國家 > 利基 > 季節（Q4）> 裝置與版位 > 廣告密度與可視度；東南亞流量的顯示廣告 RPM 多在 US 的 1/5–1/10（待以自家報表驗證）。
4. 廣告與 Core Web Vitals 不是二選一：預留版位尺寸（避免 CLS）、延遲載入首屏以下廣告、遵守 Better Ads Standards（行動版廣告密度 ≤ 30%）。
5. 無效流量是帳號層級風險：自點、刷量、付費低品質流量、機器人都可能導致永久停權（詳見 22 §5）；聯盟行銷與贊助內容必須「清楚且顯眼」揭露，且贊助連結用 `rel="sponsored"`。

## 1. AdSense 申請條件與審核

AdSense 的申請、驗證、付款與稅務已移到 22 章（正典位置），本節只留摘要：
- 官方資格只有三項加年齡：自有高品質原創內容、能存取 HTML、遵守計畫政策、年滿 18 歲；**沒有流量、文章數、網域年齡門檻**（「20–30 篇」是經驗值）。詳見 22 §1.1。

**對東南亞流量站的策略**：
- 流量 ≥ 50% 來自東南亞的站，逐平台判斷：Journey 只看 premium sessions 的絕對數量（1,000／30 天）且其他國家流量不扣分，達標即可申請（https://www.mediavine.com/blog/two-years-of-journey-by-mediavine/）；Raptive 看 Tier 1 比例（25k–99,999 需 ≥ 50%、100k+ 需 ≥ 40%；https://help.raptive.com/hc/en-us/articles/360032840891-Who-is-eligible-for-Raptive）；Mediavine 看年廣告收入 USD 5,000（https://www.mediavine.com/application-requirements/）。若都不符，路徑是 **AdSense → GAM + MCM 合作夥伴（AdX 需求）**，再視 premium sessions 成長申請 Journey。
- 若 Raptive 的 Tier 1 比例不達標，可考慮用 10 做市場分流：把英文、面向北美讀者的內容集中在獨立資產，使該資產的比例達標（注意 11 的站群風險）；Journey 不需要為此分站。

## 5. RPM 影響因素

### 5.1 影響因素（由大到小）

| 因素 | 影響幅度 | 說明 |
|---|---|---|
| **國家 Tier** | 最高可差 10 倍 | US > UK/CA/AU > 西歐/日/韓/新加坡 > 台灣/東歐/中東 > 東南亞/南亞/非洲（排序為經驗值，Google 無官方國家 RPM 排名；專案執行時以自家 AdSense 國家報表校正） |
| **利基** | 可差 5–10 倍 | 保險、金融、法律、B2B 軟體、健康（合規）最高；娛樂、八卦、遊戲、通用新聞最低 |
| **季節** | Q4 比 Q1 高 30–80%；1 月最低 | 廣告主年度預算與購物季 |
| **裝置** | 桌機 RPM 通常高於行動 20–50%（經驗值，專案執行時以自家 AdSense 裝置報表校正） | Anchor/Vignette 可補行動差距 |
| **流量來源** | 搜尋 > 直接 > 社群（Pinterest 除外）> 付費 | 搜尋流量意圖明確 |
| **廣告密度與格式** | 邊際遞減 | 第 4 個以上的版位 RPM 貢獻快速下降，且傷 CWV 與停留 |
| **可視度（Viewability）** | 可視率 70% vs 40% 可差 30% 以上 CPM | 用 lazy load 與 sticky 單元提升 |
| **使用者訊號** | 同意率（CMP）、Ad blocker 使用率 | 歐洲 CMP 同意率 70–90% 為正常 |
| **內容型態** | 長文 > 短文；列表／比較頁 > 新聞 | 捲動深度決定可視曝光 |

## 6. 廣告與 Core Web Vitals 的平衡

**規範**：所有廣告容器在 CSS 中預留固定尺寸（`min-height`），首屏以下廣告延遲載入，廣告腳本以 `async` 載入且不阻塞主執行緒；目標 CLS ≤ 0.1、INP ≤ 200ms、LCP ≤ 2.5s（CWV 定義與量測詳見 04）。

**為什麼**：廣告是內容站 CLS 的頭號來源（廣告載入後推擠內容）；Google 的頁面體驗訊號與 AdSense 的「廣告品質」評估都會懲罰糟糕體驗；同時可視度低的廣告 CPM 也低，所以「少而可視」通常比「多而被略過」賺更多。

**怎麼做**：
1. 每個廣告槽外層 `div` 設 `min-height`：行動 in-article 預留 280px（或 250px）、桌機 leaderboard 預留 90px／250px；responsive 單元用 `aspect-ratio` 或固定高度。
2. Anchor ads 由 Google 負責不推擠版面；自製 sticky 必須 `position: fixed` 且不改變文件流。
3. 首屏只放 1 個廣告（或不放），其餘延遲載入：AdSense 沒有 `data-ad-format` 的 lazy load 用法（該屬性只是格式參數，https://support.google.com/adsense/answer/9183460），需自行以 IntersectionObserver 等方式延遲插入廣告碼（不要用 `display:none` 先藏再顯示，官方說初始隱藏的單元可能不發出請求；詳見 22 §3.6）；GAM 則用 `enableLazyLoad`（fetchMarginPercent 100–200）。
4. 廣告腳本放 `<head>` 但 `async`；第三方 header bidding 用 timeout ≤ 1,000ms。
5. 字型、圖片同樣預留尺寸，避免與廣告疊加造成 CLS。
6. 用 Chrome DevTools Performance panel 的 Layout Shift 區塊確認偏移來源是否為廣告。

**驗收方式**：CrUX（Search Console 的 Core Web Vitals 報告）行動版 75 百分位 CLS < 0.1；PageSpeed Insights 實驗室 CLS 無廣告造成的偏移；AdSense「Active View 可視率」≥ 60%。

**常見錯誤**：responsive 廣告不給高度；sticky 側欄在行動版也啟用遮住內容；Auto ads 在首屏塞兩個；為了衝可視率用 `position: fixed` 蓋住內容（Better Ads 違規）。

## 7. 廣告版位最佳實務與密度上限

### 7.1 Better Ads Standards（Coalition for Better Ads，Chrome 強制執行）

| 裝置 | 違規格式 |
|---|---|
| 桌機（6 種） | 彈窗廣告；有聲自動播放影片廣告；有倒數的前置插頁（prestitial）；大型黏性廣告（超過視窗 30%）；廣告密度超過 50%；黏性影片廣告搭配廣告密度超過 30%（https://www.betterads.org/standards/） |
| 行動（10 種） | 彈窗；前置插頁（有無倒數皆算）；**廣告密度超過 30%**（分母為主要內容區域高度，排除頁首／頁尾導覽；https://www.betterads.org/mobile-ad-density-higher-than-30/）；閃爍動畫廣告；有聲自動播放影片；有倒數的後置插頁（poststitial）；全螢幕捲動覆蓋（scrollover）；大型黏性廣告（超過視窗 30%）；黏性彈出式影片廣告；黏性影片廣告搭配大型內嵌廣告 |

注意區分「標準修訂」（Coalition 新增類型）與「Chrome 執行」（Chrome 依其公告時程套用）。Chrome 自 2019-07 起全球對違規網站過濾**所有**廣告，在 Search Console 的「Ad Experience Report」可查狀態（Google 已於 2026-04-13 公告、2026-06-15 起執行返回鍵劫持（back button hijacking）為垃圾政策違規，詳見 07 第 5.4 節；AdSense vignette 同日起不再由返回鍵觸發，詳見 22 §3.2）。Chrome 2026-09-15 另在 CrUX 新增實驗性廣告指標（Ad Count、Ad Density 等），官方說明不屬於 Core Web Vitals、無門檻、未與 Better Ads 執行掛鉤（https://developer.chrome.com/blog/crux-ad-metrics ，查閱 2026-11-04；詳見 22 §2.9）。

### 7.2 密度與配置規範

**規範**：行動版廣告密度 ≤ 30%（官方定義：分子為廣告總高度，分母為主要內容區域高度，排除頁首頁尾導覽；Better Ads 硬限制，https://www.betterads.org/mobile-ad-density-higher-than-30/），實務目標 15–20%；每 1,000 字內文不超過 3 個 in-content 廣告；廣告與可點擊元素（按鈕、導覽、影片控制）距離 ≥ 150px（AdSense 對遊戲頁的建議值，通用採用）。

**怎麼做**（內容站標準配置）：

| 位置 | 行動 | 桌機 |
|---|---|---|
| 標題下／首段後 | 1 個（預留 280px） | 1 個 leaderboard 或 none |
| 內文 | 每 400–600 字 1 個，最多 4 | 同左 + 側欄 1 個 sticky 300×600 |
| 文末 | 1 個 multiplex | 1 個 multiplex |
| 錨定 | Anchor（Auto ads） | Anchor 可關 |
| 插頁 | Vignette（Auto ads，Google 限頻） | Vignette 可開 |

**驗收方式**：Ad Experience Report 狀態 Passing；用 Chrome 擴充功能或 Marfeel 等 Ad Density 工具量行動版密度；AdSense「每頁廣告數」實驗 RPM 沒有因減少版位下降。

**常見錯誤**：在 Table of Contents 與第一個 H2 之間塞 2 個廣告；短文（< 500 字）放 3 個以上；廣告標籤用「推薦閱讀」「資源」誤導。

## 8. 無效流量防範與帳號風險

無效流量與帳號安全已移到 22 §5，本節只留摘要：
- 即使是第三方造成的無效流量，責任仍在發布者；不自點、不買點擊型流量、開發與內部環境不輸出廣告碼。詳見 22 §5.1。
- 新帳號可能先遇到 Ad serving limit（通常少於 30 天、自動解除）。詳見 22 §5.2。
- 暫時停用不可申訴；永久停用有 30 天款項暫扣、用 invalid activity appeal form 申訴，駁回後不得再參加 AdSense。詳見 22 §5.3。
- 付費流量導到廣告多於內容的頁面（arbitrage）同時違反 AdSense 與 Google Ads 政策。詳見 22 §5.4。

## 9. 聯盟行銷與揭露規範

### 9.1 揭露規範

**規範**：每一個含聯盟連結的頁面，在**第一個聯盟連結之前**（通常是首段上方）放置清楚、顯眼、白話的揭露；所有聯盟／贊助連結加 `rel="sponsored"`（或 `nofollow`）；Amazon 連結頁額外含 Amazon 指定語句。

**為什麼**：
- **美國 FTC Endorsement Guides（2023 修訂）**：揭露必須「clear and conspicuous」——難以錯過（easily noticeable）且一般消費者容易理解；藏在頁尾、獨立揭露頁、折疊區、或只在社群貼文留言區，都不算。適用於任何面向美國消費者的內容，不論網站所在地。
- **Amazon Associates Operating Agreement**（2026-04-14 更新版）：要求在含 Special Links 的網站「clearly and conspicuously」揭露，指定語句為「As an Amazon Associate I earn from qualifying purchases.」（各國站有對應譯文）；違反可扣留佣金或終止帳號。2026-04 更新另新增 180 天出貨／付款上限等條款（與揭露無關）。
- **Google**：聯盟連結須用 `rel="sponsored"`（2019-09 起；`nofollow` 仍可接受）；Site reputation abuse 政策明言「affiliate links with appropriate link treatment」不是違規，但「thin affiliation」（抄商家描述、無附加價值）是（詳見 07、11）。
- **台灣**：〈公平交易委員會對於薦證廣告之規範說明〉（2005-09-23 發布，最近修正 2017-01-19）第五點：以社群網站推文（含部落客推文、論壇發言）作薦證廣告，若薦證者與廣告主間有「非一般大眾可合理預期之利益關係」而未充分揭露、足以影響交易秩序，涉及違反公平交易法第 25 條；不實薦證另依第 21 條處理（廣告主可罰 5 萬–2,500 萬元，薦證者在一定條件下負連帶責任）。公平會另有〈對於網路廣告案件之處理原則〉把網紅、直播主納入。實務上揭露做法與 FTC 相同即可。

**怎麼做**：
1. 文首揭露範本（繁中）：「本文含聯盟連結，透過連結購買我們可能獲得佣金，不影響您的價格；評測結論不受此影響。」
2. Amazon：在上述揭露後加「As an Amazon Associate I earn from qualifying purchases.」
3. 按鈕型連結旁加「（聯盟連結）」或小標；比較表內每個「查看價格」按鈕都算連結，表格上方放揭露。
4. 影片／社群：在描述最前面與畫面中同時揭露（#ad、#affiliate）。
5. 價格與庫存：Amazon 只允許顯示其提供的價格或 API（PA-API）資料；手動標註查詢日期不是替代方案（https://affiliate-program.amazon.com/help/operating/policies）。
6. 連結屬性：`<a href="..." rel="sponsored noopener" target="_blank">`。

**驗收方式**：抽查 20 頁，揭露在首個聯盟連結之前且在行動版首屏或首段可見；Screaming Frog 檢查所有外連到聯盟網域的 `rel` 屬性。

**常見錯誤**：只在頁尾或獨立「Disclosure」頁揭露；用「Disclaimer」當標題但內容是法律免責；把 Amazon 語句改寫；聯盟連結 `dofollow`。

## 10. 付費牆／訂閱內容 SEO

**規範**：希望被索引的付費或註冊才看得到的內容，必須讓 Googlebot 看到完整內容、並用 `isAccessibleForFree: false` + `hasPart`（`WebPageElement` + `cssSelector`）標記付費區塊；採用 Flexible Sampling（計量或導讀）。

**為什麼**：Google 的 paywalled content 結構化資料用來「區分付費牆與 cloaking」——Googlebot 看到完整內容、使用者看到付費牆，若沒有標記可能被視為 cloaking；反之，不讓 Googlebot 看到付費正文不是 cloaking，只是該部分無法被索引（https://developers.google.com/search/docs/appearance/structured-data/paywalled-content）。2017-10 起 Google 以 Flexible Sampling 取代 First Click Free：發布者可自選每月免費篇數（建議 10 篇／月）或導讀（lead-in）。

**怎麼做**（JSON-LD，詳細規範見 06）：

```json
{
  "@context": "https://schema.org",
  "@type": "NewsArticle",
  "headline": "標題",
  "isAccessibleForFree": false,
  "hasPart": {
    "@type": "WebPageElement",
    "isAccessibleForFree": false,
    "cssSelector": ".paywall"
  }
}
```

規則：`cssSelector` 只能用 `.class`；不可巢狀；AMP 與非 AMP 一致；若內容不應送到瀏覽器，用伺服器端付費牆（JS 前端隱藏式付費牆有另外的指引）；確認 Googlebot（驗證過的 IP）可取得完整內容。

**AI 時代的補充**：被 AIO 摘要後付費牆內容可能被「免費回答」。Google 2026-05 在 AIO 加入訂閱標籤；若要限制摘要，用 `max-snippet` 或 GSC 的 Search generative AI 控制項（詳見 08）。

**驗收方式**：Rich Results Test 無錯誤；URL 檢查工具「已轉譯的 HTML」含付費段落；GSC 無 cloaking 相關手動處置。

**常見錯誤**：用 `cssSelector: "#id"`；付費牆以 JS 把內容從 DOM 刪除但沒有標記；Googlebot 被導到登入頁。

## 11. 原生廣告／贊助內容的 SEO 與政策

**規範**：贊助內容頁面必須（1）明顯標示「贊助／廣告／Sponsored」、（2）外連用 `rel="sponsored"`、（3）由本站編輯團隊主導格式與品質、（4）不以 SEO 排名為主要目的，否則可能觸發 site reputation abuse。

**為什麼**：
- Google spam policies（查閱 2026-11-03）：site reputation abuse 的「不違規」範例包含「sponsored or advertorial content shared directly with readers through the publication itself」——關鍵是「直接給讀者看」而非「借主站權重排名」。
- 2024-11 更新後，即使主站「有參與或監督」第三方內容，若內容本質仍是第三方為了排名而放，仍算違規（2026-08-30 起 EEA 內不再套用此手動處置的排名影響，EEA 外照舊；詳見 07、11）。
- AdSense／Publisher Policies 要求贊助內容不得偽裝成編輯內容，且 AdSense 廣告不得放在「只為投放廣告而建」的頁面。
- FTC：原生廣告需讓消費者在互動前就知道是廣告（「Sponsored」「Paid Post」等明確字眼；「Promoted」「Partner」不夠清楚）。

**怎麼做**：
1. 標籤：標題上方或旁邊「贊助內容 Sponsored by 〔品牌〕」，字級不小於內文。
2. 連結：所有指向贊助商的連結 `rel="sponsored"`。
3. 歸檔：贊助文放在 `/sponsored/` 或帶明確分類，便於審計；若贊助商要求大量關鍵字導向頁，拒絕或 `noindex`。
4. 作者：署名為「贊助商提供／本站編輯部」，不冒用編輯名。
5. 結構化資料：`Article` 可加 `sponsor` 屬性（`Organization`）。
6. 不要在同一站放「優惠券區」「第三方評論區」等由外部團隊營運、為排名而設的大型區塊；若有，移除、noindex、真正改為第一方內容，或移到新的獨立網域；不要搬到子網域／子目錄，官方警告這可能被視為規避處置（https://support.google.com/webmasters/answer/9044175；詳見 11）。

**驗收方式**：抽查贊助頁有標籤、`rel="sponsored"`、分類正確；GSC 無 site reputation abuse 手動處置。

**常見錯誤**：贊助文 `dofollow` 外連；「合作文」標籤只在頁尾；賣「客座文」給 SEO 公司（典型 site reputation abuse）。
