# 02 關鍵字研究與主題規劃

> 版本：1.0 ｜ 更新日期：2026-11-03 ｜ 適用：所有 SEO 網站專案 ｜ 撰寫：Claude

## 本章摘要

1. 關鍵字研究的單位不是「關鍵字」而是「主題（topic）× 意圖（intent）」：先用 SERP 判定意圖，再把同意圖的關鍵字分群成一頁。
2. 完整流程 8 步：種子 → 擴充 → 清洗 → SERP 分析 → 分群 → 主題地圖 → 評分排序 → 內容日曆；每步都有免費工具可替代付費工具。
3. 優先順序用「機會分數 = 搜尋量分 × 難度分 × 商業價值分 × 意圖分」公式，本章給完整評分表與範例。
4. Topical authority 的實作是主題地圖（hub + spokes）：一個樞紐頁 + 8–30 篇支撐頁，內部連結雙向，並在 6 個月內把樞紐做完整。
5. 關鍵字蠶食（cannibalization）靠「一個意圖一個 URL」的主題地圖預防；內容更新與汰舊每季執行一次，依「曝光高、排名 5–20 名」優先。

## 1. 搜尋意圖分類與判定法

### 1.1 分類

| 意圖 | 使用者想要 | 典型修飾詞 | 對應內容格式 | 變現方式 |
|---|---|---|---|---|
| 資訊型（Informational） | 知道、學會 | how to、what is、為什麼、教學、guide | 教學、解釋、清單、FAQ | 廣告、名單 |
| 導航型（Navigational） | 到某個網站 / 頁面 | 品牌名、login、官網 | 品牌頁、登入頁 | 幾乎無（非自家品牌不要做） |
| 商業調查型（Commercial investigation） | 比較、評估後再買 | best、review、vs、top 10、推薦、評價 | 評測、比較表、排行 | 聯盟、廣告 |
| 交易型（Transactional） | 立即購買 / 行動 | buy、price、discount、coupon、近我、預約 | 產品頁、分類頁、落地頁 | 直接銷售、聯盟 |
| 本地型（Local） | 找附近的實體服務 | near me、地名 + 服務 | 地區服務頁、商家檔案 | 來店、來電 |

Google 自己的分類（Search Quality Rater Guidelines 用語）為 Know / Know Simple、Do、Website、Visit-in-person；Know Simple 是「可用一兩句話回答」的查詢，最容易被 AI Overviews 與精選摘要直接回答，點擊率最低（來源：Google Search Quality Rater Guidelines，最新版 2025-09，查閱 2026-11-03）。

### 1.2 判定法（以 SERP 為準，不以修飾詞為準）

**規範**：每個目標關鍵字必須實際查看目標市場的 SERP（使用對應語言 / 地區設定），記錄前 10 名的內容類型，以「多數決」判定意圖；修飾詞只作初篩。

**為什麼**：Google 以查詢的實際點擊與互動資料決定該查詢的主流意圖；同一字在不同市場意圖不同。

**怎麼做**：
1. 用 Chrome 無痕 + 語言 / 地區參數（`&gl=tw&hl=zh-TW`）或 VPN / SERP 工具查看。
2. 記錄：前 10 名有幾篇教學、幾篇評測、幾個產品頁、幾個論壇、幾個影片；是否有 AI Overviews、精選摘要、People Also Ask、購物結果、本地包、影片輪播。
3. 若前 10 名 ≥ 6 個為同一類型 → 單一意圖；否則標記為「混合意圖」，優先以最多的類型為主，並在頁面中兼顧次要意圖（例如教學頁中加一段產品推薦）。
4. 把意圖寫進關鍵字母表的「intent」欄，並記錄「SERP 主導格式」欄（listicle / how-to / 比較表 / 產品頁 / 影片 / 工具）。

**驗收方式**：關鍵字母表每筆都有 intent 與 format 欄；抽查 10% 由第二人驗證一致率 ≥ 90%。

**常見錯誤**：看到 "best" 就當商業型，但 SERP 其實是資訊型（如 "best way to learn English"）；用美國 SERP 判定其他市場的意圖。

## 2. 關鍵字研究完整流程

| 步驟 | 動作 | 產出 | 工具（付費 / 免費） |
|---|---|---|---|
| 1 種子 | 從利基列 20–50 個種子詞：產品 / 問題 / 受眾用語；從競爭者首頁與分類抓 | seed list | 腦力激盪、競爭者網站、Reddit / Facebook 群組、Google 自動完成 |
| 2 擴充 | 每個種子跑：相關字、問句、自動完成、競爭者排名字（content gap） | 原始清單（通常 5,000–50,000 筆） | Ahrefs Keywords Explorer / Semrush Keyword Magic ｜ 免費：Keyword Planner、Google 自動完成、AlsoAsked（免費額度）、AnswerThePublic（免費額度）、Ahrefs Free Keyword Generator |
| 3 清洗 | 移除：品牌字（非自家）、無關、成人 / 違規、重複；統一大小寫與空白 | 清洗後清單 | 試算表 / Python |
| 4 SERP 分析 | 對高潛力字做第 4 節的 SERP 分析 | intent、format、SERP 功能欄 | 工具 SERP 概覽 ｜ 免費：手動查 |
| 5 分群 | 把同 SERP / 同意圖的字合併為一個「主題」 | 主題清單（通常是原始的 5–15%） | Keyword Insights、Semrush Keyword Manager、Ahrefs Clusters by Parent Topic ｜ 免費：手動 / 自建腳本 |
| 6 主題地圖 | 把主題組織成 hub + spoke | 主題地圖（樹狀） | 試算表、Miro / Whimsical |
| 7 評分 | 用第 7 節公式計算機會分數 | 排序後主題清單 | 試算表 |
| 8 日曆 | 依分數與資源排進日曆 | 90 天內容日曆 | Notion / Google Sheets / Airtable |

**規範**：步驟 2 的擴充必須包含至少 3 個直接競爭者的「content gap」（他們有排名、你沒有的字），因為這是最可靠的需求證據。

**驗收方式**：關鍵字母表欄位齊全：keyword、volume、KD、CPC、intent、format、SERP features、cluster、hub、priority score、status、URL。

## 4. SERP 分析

**規範**：每個「主題」（而非每個關鍵字）在撰寫前完成一份 SERP 分析表。

**怎麼做**：

| 分析項目 | 記錄內容 | 用途 |
|---|---|---|
| SERP 功能 | AI Overviews、精選摘要、PAA、影片、圖片、購物、本地包、新聞、討論與論壇（Discussions and forums）、網站連結 | 判斷可爭取的版位與點擊率預期；AI Overviews 出現 → 預期 CTR 下降，需評估是否值得做 |
| 前 10 名網域類型 | 大型媒體 / 電商 / 論壇（Reddit、Quora）/ 利基站 / 政府 / 品牌官方 | 利基站 ≥ 3 個 → 可攻；全是大站與官方 → 難度高於 KD 顯示值 |
| 內容格式 | listicle / step-by-step / 比較表 / 計算器 / 影片 / 產品頁 | 決定你的格式（跟隨主流 + 一個差異化元素） |
| 內容長度與結構 | 前 5 名字數中位數、H2 數量、是否有表格 / 圖片 / 影片 | 作為內容規格的基準（不是越長越好，是覆蓋子主題） |
| 子主題覆蓋 | 前 10 名共同出現的 H2 / 問題 | 內容大綱的必備段落 |
| 缺口 | 前 10 名都沒回答的問題、過時資料、無第一手經驗、無在地化 | 差異化切入點 |
| 新鮮度 | 前 10 名的發佈 / 更新日期 | 判斷 Google 對此查詢是否要求新鮮度（詳見 20 章） |
| 反向連結 | 前 10 名頁面的參照網域中位數 | 低於 10 → 內容即可競爭；高於 50 → 需連結建設 |

**驗收方式**：每個主題有 SERP 分析表；內容大綱覆蓋「子主題覆蓋」欄 100% 並加入至少一個「缺口」項。

**常見錯誤**：只看 KD 數字；忽略「討論與論壇」區塊的存在（代表 Google 偏好第一手經驗，純整理型內容難以勝出）。

## 5. 關鍵字分群（clustering）

### 5.1 原則

**規範**：兩個關鍵字若在目標市場 SERP 前 10 名中有 ≥ 3–4 個相同 URL，視為同一群，應由同一頁面承接；否則分開成頁。

**為什麼**：Google 對同一頁面可排名的查詢集合，等於 Google 認為這些查詢的意圖相同；SERP 重疊是最直接的證據（Ahrefs 的 Parent Topic 與多數分群工具皆以 SERP 重疊為基礎）。

### 5.2 三種方法

| 方法 | 做法 | 適用 | 優缺點 |
|---|---|---|---|
| SERP 重疊分群 | 抓每個字的前 10 名 URL，計算兩兩重疊數，≥ 3 合併（可用圖論連通分量） | 所有專案；大量字 | 最準；需要 SERP 資料（付費 API 或工具） |
| 語意分群 | 用 embedding（如 OpenAI / 開源模型）計算相似度，再人工檢查 | 無 SERP 資料時；多語言 | 便宜；容易把「意圖不同但語意相近」的字誤合（如 "iphone 15 review" 與 "iphone 15 price"） |
| 規則 / 修飾詞分群 | 以 n-gram、修飾詞（best / how / vs）分組 | 程序化 SEO、模板化內容 | 快；粗糙，需配合 SERP 抽查 |

**怎麼做（SERP 重疊，試算表可行版）**：
1. 匯出每個關鍵字的前 10 名 URL（Ahrefs / Semrush 批次匯出或 SERP API）。
2. 對每對關鍵字計算共同 URL 數。
3. 以最高搜尋量的字為「主關鍵字」，把重疊 ≥ 3 的字併入；重複直到無變化。
4. 每群產出：主關鍵字、次要關鍵字清單、總搜尋量、平均 KD、主導格式。
5. 人工抽查 10%：確認群內意圖一致。

**驗收方式**：每群有唯一主關鍵字與唯一目標 URL；上線 3 個月後用 Search Console 驗證：同一群的查詢是否都落在同一 URL（若不是，見第 12 節蠶食處理）。

**常見錯誤**：按搜尋量把所有相關字塞進一頁（造成一頁想排 50 個不同意圖的字，結果一個都不排）；把 "X vs Y" 與 "X review" 合併。

## 6. Topical authority 與主題地圖

### 6.1 概念

Topical authority 並非 Google 官方名詞，但 Google 的文件與專利多次描述「網站在某主題的覆蓋深度與一致性」作為品質訊號：helpful content 指南問「網站是否有主要目的或焦點」；2022 年起的 helpful content system（2024-03 已併入核心排名系統）以網站層級評估內容是否以人為本（來源：Google Search Central「Creating helpful, reliable, people-first content」，查閱 2026-11-03）。實務上，完整覆蓋一個主題的網站比零散覆蓋多個主題的網站更容易在該主題的新頁面快速排名。

### 6.2 主題地圖結構

```
網站（利基：例如「個人理財」）
├── Hub 1：信用卡（樞紐頁：完整指南）
│   ├── Spoke：最佳無年費信用卡（商業型）
│   ├── Spoke：信用卡申請條件（資訊型）
│   ├── Spoke：A 銀行 vs B 銀行信用卡比較（商業型）
│   ├── Spoke：信用卡年利率怎麼算（資訊型）
│   └── …（8–30 篇）
├── Hub 2：線上借貸
│   └── …
└── Hub 3：電子錢包
    └── …
```

**規範**：
- 每個 hub 有一個樞紐頁（pillar），覆蓋主題全貌並連結所有 spoke；每個 spoke 連回 hub，並橫向連結 2–5 個相關 spoke。
- 一個 hub 的 spoke 數依 SERP 分群結果決定，通常 8–30；少於 5 的主題併入其他 hub。
- 先完成一個 hub 再開下一個（寧可 3 個完整 hub，不要 10 個各 3 篇的 hub）。
- Hub 的 URL 用子目錄或清楚的父子關係（`/credit-cards/`、`/credit-cards/no-annual-fee/`），詳見 03 章。

**怎麼做**：
1. 把第 5 節的群依「上位主題」歸類成 hub。
2. 每個 hub 列出：樞紐頁主關鍵字、spoke 清單、每個 spoke 的意圖與格式、內部連結計畫。
3. 計算每個 hub 的「完成度 = 已發佈 spoke / 規劃 spoke」，目標 6 個月內 ≥ 80%。
4. 用「主題覆蓋矩陣」對照競爭者：他們有哪些 spoke 你沒有。

**驗收方式**：主題地圖文件；Search Console 用「網頁」篩選 hub 目錄，觀察 hub 內頁面的平均排名是否隨完成度提升。

**常見錯誤**：把 hub 當成分類頁卻沒有內容（樞紐頁要有實質指南）；spoke 與 hub 之間缺少雙向連結；追熱門但與利基無關的主題稀釋焦點。

## 7. 優先順序評分模型

### 7.1 公式

```
機會分數（Opportunity Score）= V × D × B × I × (S)

V 搜尋量分（1–5）
D 難度分（1–5，難度越低分越高）
B 商業價值分（1–5）
I 意圖適配分（1–5）
S 策略係數（選填，0.5–1.5：hub 完成度、季節、新鮮度）
```

### 7.2 評分表

| 分數 | V 月搜尋量（目標市場） | D 關鍵字難度（工具 KD）/ SERP 修正 | B 商業價值 | I 意圖適配（對專案類型） |
|---|---|---|---|---|
| 5 | ≥ 10,000 | KD ≤ 10，前 10 名有 ≥ 4 個利基站 | 直接變現（聯盟高佣、產品頁）、CPC 高、或 RPM 高的主題 | 完全符合（內容站：資訊 / 商業型；電商：交易型） |
| 4 | 2,000–9,999 | KD 11–25 | 間接變現（評測導流） | 高度符合 |
| 3 | 500–1,999 | KD 26–45 | 廣告變現為主 | 部分符合 |
| 2 | 100–499 | KD 46–65 | 支撐性內容（建立權威） | 低（如導航型） |
| 1 | < 100 或零量但有證據 | KD > 65，或前 10 名全是大站 / 官方 | 無直接價值 | 不符合 |

**規則**：
- D 要用 SERP 分析修正：若工具 KD 低但前 10 名全是大型媒體或政府網站，手動降 1–2 分。
- 新站（< 6 個月）D 權重加倍（公式改為 V × D² × B × I），強迫先做低難度字。
- 內容站的 B 可用「該主題的預估 RPM × 預估流量」或聯盟佣金替代主觀評分。
- S 範例：hub 完成度 < 50% 的 spoke × 1.3（優先補齊）；季節字在旺季前 3 個月 × 1.5、淡季 × 0.5。

### 7.3 範例

| 主題（主關鍵字） | 月量 | V | KD | SERP 修正 | D | B | I | S | 分數 | 排序 |
|---|---|---|---|---|---|---|---|---|---|---|
| best credit card no annual fee | 6,500 | 4 | 32 | 利基站 3 個 | 3 | 5 | 5 | 1.0 | 300 | 1 |
| how to apply for a credit card | 12,000 | 5 | 28 | 銀行官網佔 5 席 | 2 | 3 | 5 | 1.0 | 150 | 3 |
| e-wallet a vs e-wallet b | 3,200 | 4 | 15 | 利基站 5 個 | 4 | 3 | 5 | 1.3（hub 未完成） | 312 | — |
| credit card interest rate | 1,800 | 3 | 20 | — | 4 | 3 | 5 | 1.0 | 180 | 2 |
| bank a login | 40,000 | 5 | — | 導航型 | 1 | 1 | 1 | 1.0 | 5 | 不做 |

（「e-wallet a vs e-wallet b」分數最高但屬另一 hub，實際排序需以 hub 為單位：先完成信用卡 hub 的前三名，再進入電子錢包 hub。）

**驗收方式**：每個主題有分數；日曆前 30 篇全部來自分數前 25%。

**常見錯誤**：純看搜尋量；忘記意圖適配導致內容站做了交易型字卻無法變現；新站一開始就打 KD 50+ 的字。

## 8. 內容日曆

**規範**：內容日曆以「週」為單位，每筆包含：主題 / 主關鍵字、hub、意圖、格式、目標字數（依 SERP 基準）、作者、審稿人、預定發佈日、狀態、目標 URL、內部連結來源（至少 3 個既有頁面）。

**怎麼做**：
1. 第 1 個月：每個 hub 的樞紐頁 + 該 hub 分數最高的 5–8 個 spoke。
2. 第 2–3 個月：補齊 hub 至 80% 完成度，再開新 hub。
3. 每月保留 20% 產能給：內容更新（第 13 節）、時事 / 季節字、Search Console 發現的新查詢。
4. 發佈節奏穩定優於爆量（每週固定 5 篇優於月底 20 篇）；Google 對發佈頻率無官方要求，但穩定節奏便於團隊管理與爬取。
5. 狀態流程：規劃 → 大綱 → 撰寫 → 事實查核 → SEO 審核（14 章「每篇內容發佈前」清單）→ 發佈 → 內部連結補上 → 30 天後檢查。

**驗收方式**：日曆準時率 ≥ 80%；每篇發佈後 7 天內被索引。

## 9. 長尾與零搜尋量關鍵字策略

### 9.1 長尾

**規範**：新站前 6 個月以長尾（≥ 4 字、月量 100–1,000）為主力，佔產出 ≥ 60%。

**為什麼**：長尾字競爭低、意圖明確、轉換率高；且 Google 會把表現好的長尾頁面逐步擴展到更廣泛的查詢（一個頁面通常為數十至數百個查詢排名）。

**怎麼做**：來源包括自動完成、PAA、Reddit / 論壇的提問、Search Console 中曝光 > 0 但無對應頁面的查詢、競爭者排名 11–30 名的字。

### 9.2 零搜尋量關鍵字

**規範**：工具顯示 0–10 搜尋量的字，若符合以下任一條件，仍列入日曆：（a）Search Console 已有曝光；（b）論壇 / 社群出現 ≥ 3 次相同問題；（c）屬新產品 / 新政策 / 新技術（工具資料滯後 1–3 個月）；（d）在地語言或混語查詢（工具覆蓋差）。

**為什麼**：Ahrefs 研究指出約 95% 的關鍵字月搜尋量 ≤ 10（來源：Ahrefs 關鍵字研究統計，查閱 2026-11-03），而工具對東南亞語言與混語的覆蓋明顯不足；零量字集合起來常是流量站的主要流量來源。

**怎麼做**：用「主題」而非單一字評估——一個零量字若能拉動 20 個相關零量字，整體等於一個中量字。發佈後 60 天用 Search Console 驗證真實曝光。

## 10. 多語言 / 混語市場的關鍵字注意事項

（技術實作與 hreflang 詳見 10-國際與多語言SEO.md；本節只談關鍵字研究。）

**規範**：每個目標市場 × 語言組合獨立做關鍵字研究，不得用翻譯清單取代。

**要點**：
1. **混語市場**：使用者常在同一句混用兩種語言（詳見 25 §3）。Keyword Planner 選目標地區後，語言分別跑英文與在地語言；工具量低不代表無需求，用自動完成與 Trends（地區篩選）補足。
2. **同語異市**：en-US、en-GB、en-IN 的用詞、品牌、法規不同；同一英文字在不同國家 SERP 不同，必須用該國 SERP 判定意圖。
3. **CPC / RPM 差異**：東南亞市場搜尋量大但廣告單價低，B 分數要用該市場的 RPM 估算，不要用美國值。
4. **拼寫變體與錯字**：在地市場常見拼寫變體（colour / color），Google 多數能正規化，不要為錯字建獨立頁面。
5. **翻譯 ≠ 在地化**：直接翻譯美國關鍵字清單會錯過在地需求；用在地論壇、Facebook 群組、Shopee / Lazada 搜尋建議作種子。
6. **分群需分市場**：同一主題在不同市場的 SERP 重疊不同，分群要按市場分別做。
7. **AI 生成多語內容**：若用 AI 翻譯擴張語言版本，Google 的 scaled content abuse 政策明確列出「翻譯後未加價值的大量頁面」為違規範例（來源：Google Spam Policies，查閱 2026-11-03）；每個語言版本須有在地化價值（在地價格、法規、範例）。

## 11. 季節性

**規範**：每個主題在關鍵字母表標記季節性類型（長青 / 年度季節 / 事件 / 趨勢中 / 衰退中），季節字於旺季前 8–12 週發佈或更新。

**怎麼做**：
1. Google Trends 看 5 年曲線（地區篩選）；年度重複峰值 → 季節字；單一峰值 → 事件字；持續上升 → 趨勢字。
2. 季節字的 URL 不含年份（`/christmas-gift-ideas/` 而非 `/christmas-gift-ideas-2026/`），每年更新內容與日期；title 可含年份。
3. 旺季前 8–12 週發佈 / 更新（Google 需要時間重新評估）；旺季中每週檢查排名。
4. 淡季時 S 係數降為 0.5，資源移到長青主題。

**驗收方式**：Search Console 以 16 個月期間比較，季節頁面的年比曝光成長。

## 12. 關鍵字蠶食預防

### 12.1 定義與判定

關鍵字蠶食（keyword cannibalization）：同一查詢由自家多個 URL 競爭，導致排名輪替、都排不好、連結與訊號分散。**注意**：同一查詢佔據兩個排名位置（雙排名）不是蠶食，是好事；只有在「排名不穩定且都不理想」時才是問題。

**診斷**：Search Console → 成效 → 篩選查詢 → 「網頁」分頁看是否有 ≥ 2 個 URL 分攤點擊；或用排名追蹤工具的 URL 變動報表；或 Ahrefs Site Explorer → Organic keywords → 篩選多 URL。

### 12.2 預防（規範）

1. 主題地圖執行「一個意圖一個 URL」；新主題加入前先查母表是否已有相同群。
2. 相似主題強制區分意圖與角度：`best X`（商業）、`how to choose X`（資訊）、`X vs Y`（比較）各一頁並互連。
3. 分類頁與文章頁不要瞄準同一主關鍵字（分類頁瞄準「X 總覽」，文章瞄準具體問題）。
4. 標籤頁（tag）預設 `noindex`（詳見 04 章）。
5. 每季跑一次蠶食稽核（13 章工具）。

### 12.3 處理

| 情況 | 解法 |
|---|---|
| 兩頁意圖完全相同 | 合併至表現較好的 URL，另一頁 301；合併內容的獨特段落 |
| 意圖不同但 Google 搞混 | 重寫 title / H1 / 首段強調差異；調整內部連結錨文字；在兩頁互相連結並註明差異 |
| 分類頁 vs 文章 | 分類頁改為總覽角度並加入實質導覽內容；文章聚焦具體問題 |
| 舊的年度頁（2024 版、2025 版） | 合併為單一長青 URL，舊 URL 301 |

## 13. 內容更新與汰舊策略

### 13.1 更新優先順序

**規範**：每季對全站內容做一次分級，依下表決定動作。

| 分級 | 條件（Search Console 近 3 個月 vs 前 3 個月） | 動作 |
|---|---|---|
| A 更新優先 | 曝光高、平均排名 5–20、CTR 低於同排名平均 | 重寫 title / 首段、補子主題、更新資料與日期、加表格 / 圖 |
| B 衰退 | 點擊下滑 > 30% 且排名下滑 | 檢查 SERP 是否變了（新格式、新競爭者、AI Overviews）；依新 SERP 重寫；補連結 |
| C 穩定 | 排名前 5 且穩定 | 每 6–12 個月輕量更新（日期、數據、連結） |
| D 零流量 | 發佈 > 6 個月，曝光 < 50 / 月 | 判斷：合併到相關頁（301）、改寫瞄準新意圖、或刪除（410） |
| E 過時 / 違規 | 資訊已錯誤、產品停售、政策已變 | 立即更新或下架（避免誤導使用者） |

**為什麼**：Google 以頁面與網站整體品質評估，大量低品質 / 零流量頁面會拖累整站（Google 在 helpful content 說明中建議移除無益內容可幫助其他內容表現）；但「刪除」不是萬靈丹——Google 表示單純刪舊內容不會自動提升排名，重點是提升整體有用性（來源：Google Search Central Blog 關於 helpful content 的說明，查閱 2026-11-03）。

### 13.2 更新作業規範

1. 更新時保留 URL；內容實質變更才更新「修改日期」（不要只改日期不改內容，Google 會依內容判斷實際新鮮度）。
2. 更新後在 Search Console 用 URL 檢查請求重新索引。
3. 每次更新記錄於內容日誌（日期、改了什麼、原因），30–60 天後回看成效。
4. 汰舊（刪除）前確認：是否有外部連結指向（有則 301 到最相關頁）、是否被其他頁面內部連結。

**驗收方式**：更新頁面 60 天後曝光 / 點擊變化；全站 D 級頁面比例 < 15%。

**常見錯誤**：只改日期不改內容；更新時把 URL 改成含新年份；一次刪除大量頁面未做 301。

## 14. 狀況與解法速查

| 症狀 | 可能原因 | 診斷步驟 | 解法 | 預防 |
|---|---|---|---|---|
| 工具顯示某主題搜尋量大，做了卻沒流量 | 意圖誤判；SERP 被官方 / 大站壟斷；AI Overviews 吸收 | 實際看目標市場 SERP 前 10 名類型與功能 | 轉向次要意圖或長尾；加入第一手經驗；若無可攻之處則放棄 | 寫前做 SERP 分析表 |
| 在地語言字量為 0 但明顯有需求 | 工具覆蓋不足 | 看自動完成、Trends、Search Console 既有曝光 | 以主題為單位發佈，60 天後用 Search Console 驗證 | 零量字策略（第 9 節） |
| 同一查詢排名在兩個 URL 間跳動 | 蠶食 | Search Console 查詢 → 網頁分頁 | 合併或重新區分意圖（第 12 節） | 主題地圖、一題一頁 |
| 新 hub 發了 20 篇都排在 30 名外 | hub 不完整；無內部連結；難度過高 | 檢查 hub 完成度與內部連結；比較 SERP 競爭者 | 補齊樞紐頁與雙向連結；先做低 D 字 | 新站 D² 權重 |
| 季節字旺季才發佈，沒趕上 | 發佈太晚 | Trends 看峰值時間 | 明年提前 8–12 週 | 母表季節欄 |
| 流量集中在少數頁面，其他頁零流量 | 主題分散、長尾未覆蓋 | 用 Search Console 匯出頁面點擊分佈 | 以表現好的頁面為核心擴張 spoke；D 級頁面處理 | 主題地圖先行 |
| 更新了舊文章但排名反而下滑 | 更新偏離原意圖；刪掉了原本排名的段落 | 比對更新前後排名的查詢（Search Console 比較期間） | 恢復被刪段落，保留原意圖 | 更新前匯出該頁所有排名查詢 |
