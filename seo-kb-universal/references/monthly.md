# monthly：月研究（2 小時）

目標：把 GSC 冒出來的需求（新查詢、缺專頁、衝刺區）轉成母表裡有分數的主題，排進下月日曆；處理蠶食候選；開一輪標題測試。對應 02 §7–§9、§12 與 01 §2.6 成長期三條線的「內容更新」。

## 步驟

1. 先完成當週的 weekly 步驟 2–3（同一份拉取即可）。
2. **新查詢進母表**（報告第 6 節 + 第 8 節）：
   - 取「母表沒有」且曝光 ≥ 50 的查詢；在地語言 / 混語字即使工具量為 0 也收（02 §9.2 (a)(d)）。
   - 每個查詢先判定：擴寫既有到達頁（加一節、改 H2）還是開新 spoke。判定依據是 SERP 意圖是否與到達頁相同（02 §1.2）；相同就擴寫，不開新頁以免蠶食（02 §12.2）。
   - 新主題寫一份 `serp-analysis.md` 區塊（02 §4），填 intent、format、serp_features，再填母表。
3. **評分**（02 §7）：V 用 Keyword Planner 或 GSC 曝光代理（曝光 ≥ 10,000 → 5、2,000–9,999 → 4、500–1,999 → 3、100–499 → 2、< 100 → 1，這是用曝光近似搜尋量，標「代理值」）；D 依 SERP 分析手動修正；新站 D 平方；S：hub 完成度 < 50% 的 spoke × 1.3，季節字旺季前 3 個月 × 1.5（02 §7.2、§11）。
4. **衝刺區更新清單**（報告第 3 節）：曝光最高的 5–8 頁排進下月，動作照 02 §13.1 A：重寫 title / 首段、補 SERP 共同子主題、更新資料與日期、加表格、補 3 個內部連結。更新前匯出該頁所有排名查詢（GSC 介面篩選網頁 → 查詢分頁），保留原本有排名的段落（02 §14）。
5. **蠶食候選**（報告第 7 節）：逐條看兩個 URL 的意圖。相同 → 合併到較好 URL，另一頁 301，合併獨特段落；不同 → 重寫 title / H1 / 首段強調差異、互連並調整錨文字；分類 vs 文章 → 分類改總覽角度（02 §12.3）。雙排名穩定的不碰。
6. **下月日曆**（02 §8）：新內容來自母表分數前 25%，以 hub 為單位排（先補完成度低的 hub）；保留 20% 產能給步驟 4 的更新與季節字；每筆含目標 URL、內部連結來源 ≥ 3 個既有頁。
7. **標題測試**：從報告第 4 節挑 3–5 頁開新一輪，寫入 `title-test-log.csv`；上月到期的結案。
8. 母表 `status`：規劃 → 大綱 → 撰寫 → 審核 → 發佈 → 30 天檢查（02 §8 狀態流程）；`last_reviewed` 填今天。`ops_calendar.py done monthly --note "新主題 N、更新 N、蠶食 N"`。

## 對話輸出

- 新進母表主題數與前 5 名（分數、hub、做法：擴寫 / 新頁）
- 下月更新清單 5–8 頁
- 蠶食處理決定（合併 / 區分）
- 要使用者決定的：預算內能寫幾篇、哪個 hub 先補

## 判讀提醒

- 曝光代理 V 會高估已排名主題、低估未排名主題；有 Keyword Planner 時以它為準（02 §3.1）。
- 新站前 6 個月長尾 ≥ 60%（02 §9.1），別被幾個高曝光大字帶走。
- 「消失查詢」多半是匿名化或季節，季檢再看，不要每月追。
- 在地語言查詢：語言不在 AdSense 支援清單（support.google.com/adsense/answer/9727）的頁面不能放 AdSense，母表 note 標記語言，避免排進變現頁。
