## 1. robots.txt 範本

機制與限制（500 KiB、只支援四個欄位、最具體 UA 群組勝出）詳見 04 第 2 節。**共同注意事項**：

- Google 只採用「最具體匹配」的那一組 UA 規則，**不會**把 `User-agent: *` 的規則合併進 `User-agent: Googlebot` 群組。因此下列範本把一般規則全放在 `*` 群組，AI 爬蟲另開群組時只寫 `Disallow: /`，不要為 Googlebot 單獨開群組（除非真的要給它不同規則，那就要把 `*` 的規則全部複製一份）。
- `Sitemap:` 用絕對 URL。
- 路徑大小寫敏感；非 ASCII 路徑用 percent-encoding（Google 2026-10-23 建議）。
- 部署前用本機 parser（如 Google 的 robotstxt 開源 parser 或 Screaming Frog 的 robots.txt 測試功能）驗證；部署後看 GSC「設定 → robots.txt」報表確認抓取狀態與版本，個別 URL 用 URL 檢查工具的即時測試（來源：https://support.google.com/webmasters/answer/6062598 ，查閱 2026-11-03）。

### 1.1 一般內容站（Astro / 靜態站 / 通用）

**使用情境**：內容站、流量站、企業官網；無登入區、無電商功能。

```txt
# robots.txt — 一般內容站
# 最後更新：2026-11-03

User-agent: *
# 站內搜尋與追蹤參數（限制爬取；Disallow 不保證不索引，要排除索引的頁面改為允許抓取並加 noindex）
Disallow: /search
Disallow: /search/
Disallow: /*?s=
Disallow: /*?q=
Disallow: /*?*utm_
Disallow: /*?*fbclid=
Disallow: /*?*gclid=
# 預覽 / 草稿 / API / 內部
Disallow: /preview/
Disallow: /draft/
Disallow: /api/
Disallow: /_next/        # 若為 Next.js 請改用 1.3 節範本（不要擋 /_next/static/）
Disallow: /admin/
# 明確允許資源目錄（避免上面規則誤擋）——寫具體路徑，不要用 Allow: /*.css$ 這類泛用規則：
# 泛用 Allow 不保證勝過較長的 Disallow，且 $ 不會匹配帶查詢參數的資源（/app.css?v=1）
Allow: /assets/
Allow: /static/
Allow: /images/
Allow: /fonts/

# ---- AI 訓練爬蟲（依第 2 節取捨決定；預設擋訓練、放搜尋）----
User-agent: GPTBot
User-agent: ClaudeBot
User-agent: Google-Extended
User-agent: CCBot
User-agent: Bytespider
User-agent: meta-externalagent
User-agent: Applebot-Extended
User-agent: Amazonbot
Disallow: /

Sitemap: https://example.com/sitemap-index.xml
```

**注意事項**：`Disallow: /_next/` 那行只是示意，Next.js 站請用 1.3 節；Allow 規則放在 Disallow 之後也沒問題（Google 以最長匹配決定，不看順序），但 `Allow: /*.css$` 這類泛用規則不保證勝過更長的 Disallow，且 `$` 不會匹配 `/app.css?v=1` 這類帶查詢參數的資源，所以上面改寫成具體路徑的 Allow；部署後要用帶查詢參數的資源 URL 實測（https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec）。

### 1.2 WordPress

**使用情境**：WordPress 內容站（Yoast 或 Rank Math 皆適用）。Yoast / Rank Math 可在後台編輯 robots.txt（Rank Math：General Settings → Edit robots.txt；Yoast：Tools → File editor）；若主機有實體檔案，實體檔優先。

```txt
# robots.txt — WordPress
# 最後更新：2026-11-03

User-agent: *
Disallow: /wp-admin/
Allow: /wp-admin/admin-ajax.php
Disallow: /wp-login.php
Disallow: /wp-json/            # 若前端或外掛需要 REST（例如 Gutenberg 前端元件），改為不擋
Disallow: /xmlrpc.php
Disallow: /?s=
Disallow: /search/
Disallow: /*?replytocom=
Disallow: /*/feed/             # 若有 Feedfetcher / RSS 需求（Google News、電子報）請移除此行
Disallow: /*/embed/
Disallow: /*?*utm_
Disallow: /*?*fbclid=
Disallow: /*?*gclid=
Disallow: /cgi-bin/
Disallow: /trackback/
# 不要擋以下目錄（渲染需要）：/wp-content/、/wp-includes/js/、/wp-content/uploads/

User-agent: GPTBot
User-agent: ClaudeBot
User-agent: Google-Extended
User-agent: CCBot
User-agent: Bytespider
User-agent: meta-externalagent
User-agent: Applebot-Extended
User-agent: Amazonbot
Disallow: /

Sitemap: https://example.com/sitemap_index.xml
```

**注意事項**：

- Yoast 的 sitemap 在 `/sitemap_index.xml`；Rank Math 在 `/sitemap_index.xml`；WordPress 核心（5.5+）在 `/wp-sitemap.xml`——**只保留一套**，用 SEO 外掛時核心 sitemap 會自動停用，確認 `/wp-sitemap.xml` 回 404 或 301。
- 不要寫 `Disallow: /wp-content/plugins/`（很多外掛的 CSS / JS 在裡面）。
- 「設定 → 閱讀 → 阻擋搜尋引擎索引」自 WordPress 5.3 起不再輸出 `Disallow: /`，核心改為輸出全站 robots meta `noindex`（https://developer.wordpress.org/reference/functions/do_robots/）；正式站必須取消勾選。

### 1.3 Next.js（App Router）

**使用情境**：Next.js 14–16 App Router 站；用 `app/robots.ts` 產生（見第 6 節），下方是產出的目標內容。

```txt
# robots.txt — Next.js
User-agent: *
Disallow: /api/
Disallow: /_next/data/
Disallow: /search
Disallow: /*?*utm_
Disallow: /*?*fbclid=
Disallow: /preview/
Disallow: /draft/
# 不要擋 /_next/static/ 與 /_next/image（JS、CSS、圖片最佳化端點）

User-agent: GPTBot
User-agent: ClaudeBot
User-agent: Google-Extended
User-agent: CCBot
User-agent: Bytespider
User-agent: meta-externalagent
User-agent: Applebot-Extended
User-agent: Amazonbot
Disallow: /

Sitemap: https://example.com/sitemap.xml
```

**注意事項**：Vercel 預覽環境另外用 `X-Robots-Tag: noindex` 標頭處理（第 6.6 節），不靠 robots.txt（預覽環境擋了也可能被外鏈索引）。

### 1.4 電商

**使用情境**：WooCommerce / Shopify 自訂 / Next.js Commerce；有購物車、結帳、帳戶、分面導覽。分面決策表見 03 第 8 節。

```txt
# robots.txt — 電商
User-agent: *
Disallow: /cart/
Disallow: /checkout/
Disallow: /my-account/
Disallow: /account/
Disallow: /wishlist/
Disallow: /compare/
Disallow: /search
Disallow: /*?s=
Disallow: /*?q=
# 分面 / 排序 / 檢視：擋掉所有「兩個以上參數」與排序類參數
Disallow: /*?*&
Disallow: /*?sort=
Disallow: /*?*orderby=
Disallow: /*?*order=
Disallow: /*?view=
Disallow: /*?*per_page=
Disallow: /*?*min_price=
Disallow: /*?*max_price=
Disallow: /*?*filter_
Disallow: /*?*add-to-cart=
Disallow: /*?*utm_
# 分頁保留可爬：不要擋 /page/N/ 與單參數 ?page=（上面的規則本就不會擋到它們）；
# 不要再加 Allow: /*?page= 這類廣泛 Allow，它比 Disallow: /*?*& 更具體時會把 ?page=2&sort=… 放行

User-agent: GPTBot
User-agent: ClaudeBot
User-agent: Google-Extended
User-agent: CCBot
User-agent: Bytespider
User-agent: meta-externalagent
User-agent: Applebot-Extended
User-agent: Amazonbot
Disallow: /

Sitemap: https://example.com/sitemap_index.xml
```

**注意事項**：`Disallow: /*?*&` 會擋掉所有含兩個以上參數的 URL，包括 `?page=2&sort=…`；分頁只保留單參數版本（不要加 `Allow: /*?page=`，它比 `Disallow: /*?*&` 更具體，會把 `?page=2&sort=…` 放行；每條規則都要用實際 URL 逐一測試）。若你的「品牌」或「價格區間」分面有搜尋需求，應做成靜態路徑（`/laptops/asus/`）而非參數，就不受此規則影響。電商若使用 Google Merchant Center，`srsltid` 參數 Google 會自己處理，不必擋。

| `Diffbot`、`omgili`、`ImagesiftBot`、`PetalBot`、`Timpibot` | 各家 | 多為訓練 / 資料蒐集 | **無官方文件，依社群觀察**（是否遵守 robots.txt 各家觀察不一致） | — | 無官方文件，依社群觀察 |

重要補充：

- Google 於 2026-10-30 在文件中表示「打算支援」一個跨業界共用的機器可讀 AI 訓練偏好訊號（IETF AIPREF 方向），Google 目標於 2027 年支援 IETF AIPREF 共用 AI 訓練控制，尚未承諾確切日期（來源：https://developers.google.com/search/blog/2026/10/ai-training-control ，查閱 2026-11-03），目前尚未生效；Cloudflare 的 Content Signals（`search` / `ai-input` / `ai-train`）是另一套、非 Google 標準，詳見 08 與第 13 節。
- `robots.txt` 是自願遵守；真正擋不守規矩的爬蟲要靠 Cloudflare AI Crawl Control / WAF（第 13 節）。
- 任何「使用者觸發」類（`ChatGPT-User`、`Perplexity-User`、`Claude-User`、`meta-externalfetcher`、Google 的 user-triggered fetchers）在設計上就不一定看 robots.txt。

### 2.2 取捨建議（依專案類型）

| 專案類型 | 訓練類（GPTBot、ClaudeBot、Google-Extended、CCBot、meta-externalagent、Applebot-Extended、Amazonbot、Bytespider） | 搜尋 / 引用類（OAI-SearchBot、Claude-SearchBot、PerplexityBot、meta-webindexer、Applebot、Bingbot） | 使用者觸發類 |
|---|---|---|---|
| 流量站（AdSense / 聯盟） | **預設擋**：內容被拿去訓練不會帶來流量，且會被用來回答問題減少點擊 | **預設放**：AI 搜尋的引用是新流量來源（詳見 08） | 不特別處理 |
| 電商 | 擋或放皆可；商品資料被訓練影響小 | **放**：購物助理需要抓到商品頁 | 放 |
| 企業官網 / SaaS | **放**（品牌希望被 AI 正確描述） | 放 | 放 |
| 付費內容 / 新聞 | 擋 | 視授權談判；可用 `nosnippet` / `max-snippet` 限制摘要 | 視授權 |

決定後把 token 清單寫進 1.x 範本的 AI 區塊；**每季重新查一次**各家文件（token 會新增 / 改名，例如 Anthropic 2025–2026 從單一 ClaudeBot 擴為三個；Google-NotebookLM 2026-07 改名 Google-GeminiNotebook）。

## 3. XML Sitemap 與 Sitemap Index 範本

規範（50,000 URL / 50 MB、lastmod 要真實、不放 noindex / 非 canonical）詳見 04 第 4 節。

### 3.1 Sitemap index

**使用情境**：任何超過一種內容類型或超過數千頁的站。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap>
    <loc>https://example.com/sitemap-posts-1.xml</loc>
    <lastmod>2026-11-03T08:00:00+08:00</lastmod>
  </sitemap>
  <sitemap>
    <loc>https://example.com/sitemap-pages.xml</loc>
    <lastmod>2026-10-20T08:00:00+08:00</lastmod>
  </sitemap>
  <sitemap>
    <loc>https://example.com/sitemap-categories.xml</loc>
    <lastmod>2026-11-01T08:00:00+08:00</lastmod>
  </sitemap>
  <sitemap>
    <loc>https://example.com/sitemap-images.xml</loc>
    <lastmod>2026-11-03T08:00:00+08:00</lastmod>
  </sitemap>
</sitemapindex>
```

**注意事項**：index 不能再包 index（只能一層）；index 內每個 `<sitemap>` 的 `<lastmod>` 指該子 sitemap 檔案內容的實際變更時間（不是其中最新 URL 的更新時間；沒有可靠時間就省略）（https://www.sitemaps.org/protocol.html#sitemapIndexTagDefinitions）。

### 3.2 標準 urlset（含 hreflang 與圖片）

**使用情境**：文章 / 頁面；多語言站用 `xhtml:link`；圖片搜尋重要（食譜、產品、DIY）時加 `image:image`。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"
        xmlns:xhtml="http://www.w3.org/1999/xhtml"
        xmlns:image="http://www.google.com/schemas/sitemap-image/1.1">
  <url>
    <loc>https://example.com/en/labor-insurance-rate-table/</loc>
    <lastmod>2026-10-28T10:15:00+08:00</lastmod>
    <xhtml:link rel="alternate" hreflang="en" href="https://example.com/en/labor-insurance-rate-table/"/>
    <xhtml:link rel="alternate" hreflang="zh-TW" href="https://example.com/zh-tw/labor-insurance-rate-table/"/>
    <xhtml:link rel="alternate" hreflang="x-default" href="https://example.com/en/labor-insurance-rate-table/"/>
    <image:image>
      <image:loc>https://example.com/images/labor-insurance-table-2026.webp</image:loc>
    </image:image>
  </url>
  <url>
    <loc>https://example.com/zh-tw/labor-insurance-rate-table/</loc>
    <lastmod>2026-10-28T10:15:00+08:00</lastmod>
    <xhtml:link rel="alternate" hreflang="en" href="https://example.com/en/labor-insurance-rate-table/"/>
    <xhtml:link rel="alternate" hreflang="zh-TW" href="https://example.com/zh-tw/labor-insurance-rate-table/"/>
    <xhtml:link rel="alternate" hreflang="x-default" href="https://example.com/en/labor-insurance-rate-table/"/>
```

**注意事項**：每個語言版本都要有自己的 `<url>` 且列出完整叢集（含自己）；`<priority>`、`<changefreq>` Google 忽略，可省；image 擴充的 `caption` / `title` / `geo_location` / `license` 已停用（2022），只留 `image:loc`。`<loc>` 必須與 canonical 一字不差（含尾斜線）。

## 4. nginx 轉址與標頭規則

**使用情境**：自管 VPS（靜態站、WordPress / PHP、Node 反向代理；`location /` 依類型三選一）。原則：HTTP → HTTPS 與 www → 非 www 在 `server` 層一跳到最終主機名；尾斜線 / index 檔的正規化在主站 server 內是另一跳（所以 `http://www.example.com/path` 最多兩跳：先到 `https://example.com/path`，再到 `https://example.com/path/`）。要真正一跳到位，要用 `map` 先算出完整最終 URL 再 `return 301`；小寫轉換本範本**未實作**（見下方註解）。

```nginx
# ===== 1) HTTP → HTTPS（所有主機名）=====
server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;
    return 301 https://example.com$request_uri;   # 直接到最終主機名，避免二跳
}

# ===== 2) www → 非 www（HTTPS）=====
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name www.example.com;
    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    return 301 https://example.com$request_uri;
}

# ===== 3) 主站 =====
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name example.com;
    root /var/www/example.com/public;
    index index.html index.php;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    # --- 大寫路徑 → 小寫（需 nginx 編譯含 PCRE；靜態站適用；WordPress 慎用，因為 wp-admin 有大小寫檔名時會壞）---
    # 若需要，改用 OpenResty / lua 或在應用層處理。
    # location ~ [A-Z] { return 301 https://example.com$request_uri_lowercase; }  # 需 lua 產生變數；示意

    # --- 尾斜線：目錄式 URL 統一加斜線（WordPress 預設）---
    # 無副檔名且不以 / 結尾 → 301 加斜線
    location ~ ^([^.\?]*[^/])$ {
        return 301 https://example.com$1/$is_args$args;   # 加 $is_args$args 保留查詢字串，否則 ?page=2 會遺失
    }
    # 若選擇「無尾斜線」風格，改為：
    # rewrite ^/(.*)/$ /$1 permanent;

    # --- 移除 index.html / index.php ---
    # $request_uri 含查詢字串，所以比對要允許可選的 ?query，目的地再用 $is_args$args 帶回
    if ($request_uri ~* "^(.*/)index\.(html|php)(\?.*)?$") {
        return 301 https://example.com$1$is_args$args;
    }

    # --- 舊 URL 對應表（改版時用 map，大量時放獨立檔）---
    # 在 http {} 區塊加入：
    # map $uri $new_uri {
    #     include /etc/nginx/redirects.map;   # 每行：/old-path/ /new-path/;
    # }
    # 這裡：
    # if ($new_uri) { return 301 https://example.com$new_uri; }

    # --- 靜態資源長快取（指紋檔名）---
    location ~* \.(js|css|png|jpg|jpeg|gif|webp|avif|svg|ico|woff2|woff|ttf)$ {
        expires 365d;
        add_header Cache-Control "public, max-age=31536000, immutable";
        include /etc/nginx/snippets/security-headers.conf;   # 此 location 有自己的 add_header，server 層的安全標頭不會繼承，要再 include
        access_log off;
    }

    # --- HTML：CDN 快取、瀏覽器不快取（依站台類型三選一）---
    # (a) 靜態站
    location / {
        try_files $uri $uri/ =404;
        add_header Cache-Control "public, max-age=0, s-maxage=600, stale-while-revalidate=86400";
        include /etc/nginx/snippets/security-headers.conf;   # 同上：有 add_header 的 location 要再 include
    }
    # (b) WordPress / PHP：try_files 之外必須有 PHP FastCGI，否則 .php 會以原始碼輸出
    # location / {
    #     try_files $uri $uri/ /index.php?$args;
    #     add_header Cache-Control "public, max-age=0, s-maxage=600, stale-while-revalidate=86400";
    #     include /etc/nginx/snippets/security-headers.conf;
    # }
    # location ~ \.php$ {
    #     try_files $uri =404;
    #     fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    #     fastcgi_index index.php;
    #     include fastcgi_params;
    #     fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    # }
    # (c) Node / Next.js 反向代理（不要用 try_files … /index.php，會造成 404 或迴圈）
    # location / {
    #     proxy_pass http://127.0.0.1:3000;
    #     proxy_http_version 1.1;
    #     proxy_set_header Host $host;
    #     proxy_set_header X-Real-IP $remote_addr;
    #     proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    #     proxy_set_header X-Forwarded-Proto https;
    #     add_header Cache-Control "public, max-age=0, s-maxage=600, stale-while-revalidate=86400";
    #     include /etc/nginx/snippets/security-headers.conf;
    # }

    # --- 安全標頭（第 12 節；server 層）---
    # nginx 的 add_header 不繼承：只要某個 location 自己有 add_header，server 層的這些標頭就不會套用到它，
    # 所以上面每個有 add_header 的 location 都再 include 一次（https://nginx.org/en/docs/http/ngx_http_headers_module.html#add_header）
    include /etc/nginx/snippets/security-headers.conf;

    # --- 壓縮 ---
    gzip on; gzip_types text/plain text/css application/json application/javascript text/xml application/xml image/svg+xml;
    # brotli on; brotli_types ...;   # 需 ngx_brotli 模組
}
```

`/etc/nginx/redirects.map` 範例（來源：03 第 13 節的對應表）：

```
/old-category/old-post/   /topic/new-post/;
/about-us.html            /about/;
```

**注意事項**：

- `if` 在 nginx 是「邪惡」的（`if is evil`），只用在 `return` / `rewrite` 單一指令的情境；複雜邏輯用 `map`。
- 轉址後用 `curl -sIL` 確認跳數符合預期：正規 URL 直接 200；`http://www.example.com/path` 這類最差情況不超過兩跳（主機名一跳 + 尾斜線一跳）。
- WordPress 自己也會做尾斜線與 canonical 轉址（`redirect_canonical`），與 nginx 規則一致即可，不要互相打架。
- 維護模式：`return 503;` 並加 `add_header Retry-After 3600 always;`（沒有 `always` 時 add_header 只對 2xx / 3xx 生效，503 不會帶 Retry-After；https://nginx.org/en/docs/http/ngx_http_headers_module.html#add_header）。

## 5. Apache .htaccess 規則

**使用情境**：共享主機 WordPress（cPanel）。放在網站根目錄 `.htaccess` 的 `# BEGIN WordPress` 區塊**之前**。

```apache
# ===== 轉址：HTTPS + 非 www 一跳到位 =====
RewriteEngine On
# 注意：若 TLS 在反向代理 / CDN（Cloudflare Flexible、負載平衡器）終止，Apache 收到的是 HTTP，
# %{HTTPS} 永遠是 off → 會造成無限轉址迴圈。因此同時檢查代理送來的 X-Forwarded-Proto：
# 只有「HTTPS off 且 X-Forwarded-Proto 不是 https」才算真正的 HTTP 請求。
# 正式環境請在代理層設定 X-Forwarded-Proto（Cloudflare 會自動帶；自架 nginx 用 proxy_set_header X-Forwarded-Proto $scheme），
# 並在 Apache 用 RemoteIPHeader / 或只信任代理 IP，避免外部客戶端偽造此標頭。
RewriteCond %{HTTPS} off
RewriteCond %{HTTP:X-Forwarded-Proto} !=https
RewriteRule ^ https://example.com%{REQUEST_URI} [L,R=301]
RewriteCond %{HTTP_HOST} ^www\. [NC]
RewriteRule ^ https://example.com%{REQUEST_URI} [L,R=301]

# ===== 移除 index.php / index.html =====
RewriteCond %{THE_REQUEST} \s/+(.*/)?index\.(php|html)[\s?] [NC]
RewriteRule ^(.*/)?index\.(php|html)$ /$1 [L,R=301]

# ===== 尾斜線：目錄式統一加斜線（WordPress 風格）=====
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_URI} !(.*)/$
RewriteCond %{REQUEST_URI} !\.[a-zA-Z0-9]{2,5}$
RewriteRule ^(.*)$ /$1/ [L,R=301]

# ===== 大寫 → 小寫（需在 httpd.conf 啟用 RewriteMap lc int:tolower；共享主機通常不可用）=====
# RewriteCond %{REQUEST_URI} [A-Z]
# RewriteRule ^(.*)$ /${lc:$1} [L,R=301]

# ===== 舊 URL 對應（少量用 Redirect；大量用 RewriteMap 或外掛 Redirection）=====
Redirect 301 /old-page/ https://example.com/new-page/

# ===== 靜態資源快取 =====
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType image/avif "access plus 1 year"
  ExpiresByType image/png "access plus 1 year"
  ExpiresByType image/jpeg "access plus 1 year"
  ExpiresByType image/svg+xml "access plus 1 year"
  ExpiresByType text/css "access plus 1 year"
  ExpiresByType application/javascript "access plus 1 year"
  ExpiresByType font/woff2 "access plus 1 year"
</IfModule>

# ===== 安全標頭 =====
<IfModule mod_headers.c>
  Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
  Header always set X-Content-Type-Options "nosniff"
  Header always set X-Frame-Options "SAMEORIGIN"
  Header always set Referrer-Policy "strict-origin-when-cross-origin"
  Header always set Permissions-Policy "camera=(), microphone=(), geolocation=()"
</IfModule>
```

**注意事項**：`.htaccess` 每次請求都解析，規則越多越慢；對應表超過 200 條建議用 Cloudflare Bulk Redirects 或 Redirection 外掛（存 DB）。`R=301` 在測試期間可先用 `R=302` 避免瀏覽器快取錯誤規則，確認無誤再改 301。

## 6. Next.js（App Router）設定

以下對應 Next.js 15–16（API 以官方文件 2026-08 版為準，查閱 2026-11-03）。版本注意：Next.js 16 起 `generateSitemaps` 的 `id` 為 Promise；`params` / `searchParams` 自 15 起為 Promise；`themeColor` / `viewport` 自 14 起移到 `generateViewport`。

### 6.1 `next.config.ts`：尾斜線、轉址、標頭

**使用情境**：所有 Next.js 專案的基礎。

```ts
// next.config.ts
import type { NextConfig } from 'next'

const securityHeaders = [
  { key: 'Strict-Transport-Security', value: 'max-age=31536000; includeSubDomains; preload' },
  { key: 'X-Content-Type-Options', value: 'nosniff' },
  { key: 'X-Frame-Options', value: 'SAMEORIGIN' },
  { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
  { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
]

const nextConfig: NextConfig = {
  trailingSlash: true,          // 與 03 章定案的尾斜線規則一致；預設 false
  poweredByHeader: false,
  images: {
    formats: ['image/avif', 'image/webp'],
    deviceSizes: [360, 414, 640, 768, 1024, 1280, 1536],
    remotePatterns: [{ protocol: 'https', hostname: 'cdn.example.com' }],
  },
  async redirects() {
    return [
      // 舊 URL 對應（大量時從 JSON 讀入）
      { source: '/old-post/', destination: '/topic/new-post/', permanent: true },
      // 移除 ?page=1：不要在這裡做。redirects() 會把原始 query 帶到 destination，destination 同路徑會形成轉址迴圈
      // （https://nextjs.org/docs/app/api-reference/config/next-config-js/redirects）；改在 middleware.ts 處理：
      //   const url = request.nextUrl.clone()
      //   if (url.searchParams.get('page') === '1') { url.searchParams.delete('page'); return NextResponse.redirect(url, 308) }
    ]
  },
  async headers() {
    const headers = [{ source: '/:path*', headers: securityHeaders }]
    // Vercel 預覽環境全站 noindex（正式環境 VERCEL_ENV === 'production'）
    if (process.env.VERCEL_ENV && process.env.VERCEL_ENV !== 'production') {
      headers.push({ source: '/:path*', headers: [{ key: 'X-Robots-Tag', value: 'noindex, nofollow' }] })
    }
    return headers
  },
}

export default nextConfig
```

**注意事項**：`www` → 非 www 與 HTTP → HTTPS 在 Vercel 由「Domains」設定的 redirect 處理（把 `www.example.com` 設為 redirect 到 `example.com`），不要在 `redirects()` 裡做主機名轉址（會變二跳）。自管 Node 時交給 nginx（第 4 節）。

### 6.2 `app/layout.tsx`：全站 metadata 與 `metadataBase`

```tsx
// app/layout.tsx
import type { Metadata, Viewport } from 'next'

export const metadata: Metadata = {
  metadataBase: new URL('https://example.com'),   // 一定要設，否則相對 URL 會 build error
  title: { default: 'Example', template: '%s | Example' },
  description: 'Default description, 150–160 字元。',
  alternates: { canonical: '/' },                 // 根頁 canonical；子頁各自覆寫
  openGraph: { type: 'website', siteName: 'Example', locale: 'en_US' },
  twitter: { card: 'summary_large_image' },
  robots: {
    index: true, follow: true,
    googleBot: { index: true, follow: true, 'max-image-preview': 'large', 'max-snippet': -1, 'max-video-preview': -1 },
  },
  verification: { google: 'GSC-驗證碼' },        // 用網域資源驗證時可省
}

export const viewport: Viewport = { width: 'device-width', initialScale: 1, themeColor: '#ffffff' }

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>

```

**注意事項**：`metadata` 是**淺合併**——子頁若設了 `openGraph`，會整個取代 layout 的 `openGraph`（連 `siteName` 都要重寫）；建議抽成 `shared-metadata.ts` 展開。`robots` 不要在 layout 設 `index: false`（會被全站繼承）。

### 6.3 `app/[locale]/[topic]/[slug]/page.tsx`：動態 metadata、canonical、hreflang

路由含語言段（`/en/…`、`/ja/…`），與 hreflang、sitemap 使用同一組 URL；canonical、hreflang、sitemap 都從同一個 URL 產生函式取值，避免三者不一致。

```ts
// lib/urls.ts —— 單一 URL 產生函式，canonical / hreflang / sitemap 共用
export const LOCALES: Record<string, string> = { en: 'en', ja: 'ja' }   // 路由 locale 段 → hreflang 代碼
export function localizedUrls(topic: string, slug: string): Record<string, string> {
  return Object.fromEntries(Object.entries(LOCALES).map(([seg, tag]) => [tag, `/${seg}/${topic}/${slug}/`]))
}
```

```tsx
// app/[locale]/[topic]/[slug]/page.tsx
import type { Metadata } from 'next'
import { notFound } from 'next/navigation'
import { getPost } from '@/lib/posts'
import { LOCALES, localizedUrls } from '@/lib/urls'

type Props = { params: Promise<{ locale: string; topic: string; slug: string }> }

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { locale, topic, slug } = await params
  const post = await getPost(topic, slug)
  if (!post || !LOCALES[locale]) return { robots: { index: false } }   // 404 頁不索引（page 本身也會 notFound()）
  const urls = localizedUrls(topic, slug)       // { en: '/en/topic/slug/', ja: '/ja/topic/slug/' }
  const path = urls[LOCALES[locale]]             // 目前語言版本的路徑
  return {
    title: post.title,                            // 套用 layout 的 template
    description: post.excerpt,
    alternates: {
      canonical: path,                            // 相對路徑 + metadataBase → 絕對 URL；自指
      languages: { ...urls, 'x-default': urls['en'] },
    },
    openGraph: {
      type: 'article', siteName: 'Example', locale: 'en_US',
      title: post.title, description: post.excerpt, url: path,
      images: [{ url: post.ogImage, width: 1200, height: 630, alt: post.title }],
      publishedTime: post.publishedAt, modifiedTime: post.updatedAt, authors: [post.author.name],
    },
    twitter: { card: 'summary_large_image', title: post.title, description: post.excerpt, images: [post.ogImage] },
    robots: post.noindex ? { index: false, follow: true } : undefined,
  }
}

export default async function Page({ params }: Props) {
  const { locale, topic, slug } = await params
  const post = await getPost(topic, slug)
  if (!post || !LOCALES[locale]) notFound()       // 在串流開始前判定才會真正回 404；串流已開始時 Next.js 維持 200 並注入 noindex
  return <article>{/* ... */}</article>
}
```

**注意事項**：`generateMetadata` 只能在 Server Component；同一檔不能同時 export `metadata` 與 `generateMetadata`。若啟用 Cache Components / `'use cache'`，回傳值要可序列化（`metadataBase` 用字串）。Streaming metadata（15.2+）會把 meta 放進 `<body>`，Google 可讀；若擔心其他爬蟲，在 `next.config` 設 `htmlLimitedBots` 或維持預設（Next.js 內建清單已含常見非 JS bot）。

### 6.4 `app/robots.ts`

```ts
// app/robots.ts
import type { MetadataRoute } from 'next'

const AI_TRAINING_BOTS = ['GPTBot', 'ClaudeBot', 'Google-Extended', 'CCBot', 'Bytespider', 'meta-externalagent', 'Applebot-Extended', 'Amazonbot']

export default function robots(): MetadataRoute.Robots {
```

### 6.5 `app/sitemap.ts`（含多檔分割與 hreflang）

```ts
// app/sitemap.ts —— 單檔版（< 50,000 URL）
import type { MetadataRoute } from 'next'
import { getAllPosts, getAllTopics } from '@/lib/posts'
import { localizedUrls } from '@/lib/urls'          // 與 6.3 共用同一 URL 產生函式

const BASE = 'https://example.com'

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const [posts, topics] = await Promise.all([getAllPosts({ indexable: true }), getAllTopics()])
  const staticPages: MetadataRoute.Sitemap = [{ url: `${BASE}/`, lastModified: new Date('2026-10-01') }]
  const topicPages = topics.map(t => ({ url: `${BASE}/${t.slug}/`, lastModified: t.updatedAt }))
  // 每個語言版本都要有自己的 <url>，且每筆都附完整語言清單（含自己）
  // https://developers.google.com/search/docs/specialty/international/localized-versions#sitemap
  const postPages = posts.flatMap(p => {
    const languages = Object.fromEntries(
      Object.entries(localizedUrls(p.topic, p.slug)).map(([tag, path]) => [tag, `${BASE}${path}`]),
    )
    return Object.values(languages).map(url => ({
      url,
      lastModified: p.updatedAt,                     // 真實更新時間，不要 new Date()
      alternates: { languages },
    }))
  })
  return [...staticPages, ...topicPages, ...postPages]
}
```

### 6.6 其他

- **404**：`app/not-found.tsx` 會回 404 狀態碼；動態頁用 `notFound()`，但要在串流開始前（取得資料後立即）呼叫——串流已開始時 Next.js 會維持 200 並注入 `<meta name="robots" content="noindex">`（https://nextjs.org/docs/app/api-reference/file-conventions/not-found）。
- **預覽 / 草稿**：Draft Mode 的頁面加 `robots: { index: false }` 並在 `headers()` 加 X-Robots-Tag（6.1）。
- **圖片**：`<Image src loading="eager" fetchPriority="high" sizes="(max-width: 768px) 100vw, 768px" />`：LCP 圖只保留一種策略——`loading="eager"`（不 lazy）+ `fetchPriority="high"`（抓取優先級）；Next.js 文件明寫已用 `loading` 或 `fetchPriority` 時不應再加 `preload`（會輸出 `<link rel="preload">`），二者擇一（來源：https://nextjs.org/docs/app/api-reference/components/image#preload ，查閱 2026-11-03）；Next.js 16 已將 `priority` 標為 deprecated、改用 `preload`，舊版仍用 `priority`（https://nextjs.org/docs/app/api-reference/components/image#priority）。
- **字型**：`next/font/local` 自動 preload 與 `font-display: swap`。
- **第三方腳本**：`<Script src strategy="lazyOnload" />`（第 11.5 節）。
- **JSON-LD**：在 Server Component 內 `<script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(data).replace(/</g, '\u003c') }} />`（`replace` 跳脫 `<`，避免資料中的 `</script>` 提前結束標籤造成注入；https://nextjs.org/docs/app/guides/json-ld；結構化資料內容詳見 06）。

**注意事項**：

- `useSeoMeta` / `useHead` 必須在 `<script setup>` 頂層或 `setup()` 內呼叫，**不要放在 `onMounted`**（只會在客戶端執行，Googlebot 第一次抓取看不到）。
- `routeRules` 的 `robots` 鍵語法（`false` / 字串 / 物件三種）依 nuxtseo.com「Route Rules」文件（查閱 2026-11-03）；Nuxt 核心的 routeRules 只有 `redirect` / `proxy` / `ssr` / `cors` / `headers` / `swr` / `isr` / `prerender` / `noScripts` / `appMiddleware`。
- **同元件切換 slug 時 canonical 是否更新**（例如 `/a/x` → `/a/y` 在同一個 `[slug].vue` 內以客戶端導覽切換）：上面範例用 `route.path` 字串取值，不是 reactive getter，理論上只在元件首次 setup 時計算；屬**專案執行時驗證**——驗法：在瀏覽器以站內連結切換到另一篇後，DevTools 檢查 `<link rel="canonical">` 是否跟著變；若沒有，改成 `href: () => `https://example.com${route.path}``（getter 形式）或啟用 nuxt-seo-utils 自動 canonical。Googlebot 抓的是 SSR 首次輸出，所以這個問題影響的是使用者端分享 / 工具檢測，但仍應修正。
- 尾斜線：Nuxt 預設無斜線；若要加斜線用 Nitro 的 `routeRules` 或在 CDN 層做 301，並確保全站連結一致。
- `@nuxtjs/sitemap` 的 `lastmod` 來源要接內容系統（Nuxt Content 會自動）。
- i18n：用 `@nuxtjs/i18n`，sitemap 與 hreflang 會自動整合（詳見 10）。

### 11.2 字型：自架、子集、preload、swap

```html
<link rel="preload" href="/fonts/inter-latin-var.woff2" as="font" type="font/woff2" crossorigin>
<style>
  @font-face {
    font-family: 'Inter';
    src: url('/fonts/inter-latin-var.woff2') format('woff2');
    font-weight: 100 900;
    font-display: swap;            /* 文字先用系統字顯示；若 CLS 嚴重改 optional */
    unicode-range: U+0000-00FF, U+0131, U+0152-0153, U+2BB-2BC, U+2C6, U+2DA, U+2DC, U+2000-206F, U+2074, U+20AC, U+2122, U+2191, U+2193, U+2212, U+2215, U+FEFF, U+FFFD;
  }
  /* 讓 fallback 字型的度量貼近正式字型，減少 swap 時的位移 */
  @font-face {
    font-family: 'Inter Fallback';
    src: local('Arial');
    size-adjust: 107%; ascent-override: 90%; descent-override: 22%; line-gap-override: 0%;
  }
  body { font-family: 'Inter', 'Inter Fallback', system-ui, sans-serif; }
</style>
```

**注意事項**：中文字型檔很大，用 `pyftsubset` 或 `glyphhanger` 依頁面實際字元子集化，或直接用系統字（`system-ui, -apple-system, "Noto Sans TC"`）不自架；Next.js 的 `next/font` 與 Nuxt 的 `@nuxt/fonts` 會自動做 size-adjust fallback。

### 11.3 廣告位預留空間防 CLS（AdSense）

**使用情境**：所有有廣告的流量站。原理：容器先佔住高度，廣告晚到也不推擠內容。

```html
<style>
  .ad-slot { display: block; width: 100%; overflow: hidden; margin: 24px 0; }
  /* 依版位的「最常出現尺寸」預留；用 aspect-ratio 或 min-height */
  .ad-slot--leaderboard { min-height: 90px; }                 /* 728×90 / 970×90 */
  .ad-slot--rect { min-height: 250px; }                       /* 300×250 / 336×280 */
  .ad-slot--in-article { min-height: 280px; }
  @media (max-width: 767px) {
    .ad-slot--leaderboard { min-height: 100px; }              /* 320×100 */
    .ad-slot--rect { min-height: 250px; }
  }
  /* 文章內 / 底部 anchor 以外，不在視窗頂部動態插入任何東西 */
</style>

<div class="ad-slot ad-slot--rect">
  <!-- 固定尺寸單元優於響應式 'auto'（註解不能放在標籤內：註解的 > 會提前結束 <ins> 標籤）-->
  <ins class="adsbygoogle"
       style="display:inline-block;width:336px;height:280px"
       data-ad-client="ca-pub-XXXXXXXXXXXXXXXX"
       data-ad-slot="1234567890"></ins>
</div>
<script>(adsbygoogle = window.adsbygoogle || []).push({});</script>
```

```html
<!-- AdSense 主腳本：async，放 head 或 body 底部皆可；不要用 Rocket Loader 或快取外掛「延遲所有 JS」把它延後到互動後（會降低廣告收入與可視度，權衡見 09）-->
<script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-XXXXXXXXXXXXXXXX" crossorigin="anonymous"></script>
```

**注意事項**：

- 自動廣告（Auto ads）會在任意位置插入 → 若 CLS 不佳，到 AdSense 後台「廣告 → 按網站 → 編輯」關閉 Banner / Multiplex 等頁內格式的自動插入，只保留錨定與你手動放的單元；或在 Banner advanced settings 設「Maximum number of ads on a page」「Minimum distance between ads」並用 Excluded areas 排除區塊（舊的「廣告載入」滑桿已於 2026-04-16 移除，詳見 22 章 §3.1）。
- 響應式單元（`data-ad-format="auto"`）高度不可預測；若要用，容器至少給 `min-height: 250px`。
- 廣告在首屏（above the fold）會與 LCP 搶資源，流量站建議首屏只放一個小單元或不放。
- Ezoic / Mediavine / Raptive 等平台有自家 CLS 設定（placeholder），開啟它。

### 11.5 延遲載入第三方腳本（分析、像素、聊天）

**使用情境**：非廣告的第三方腳本（Facebook Pixel、TikTok Pixel、Hotjar、Tawk.to、社群嵌入）。原則：互動後或閒置時再載入。

```html
<script>
  // 在首次互動後載入第三方腳本；否則等 5 秒後再趁閒置載入（requestIdleCallback 的 timeout 是「最晚多久一定執行」的上限，不是延遲）
  (function () {
    var loaded = false;
    function loadThirdParty() {
      if (loaded) return; loaded = true;
      ['https://connect.facebook.net/en_US/fbevents.js', 'https://static.hotjar.com/c/hotjar-XXXX.js?sv=6'].forEach(function (src) {
        var s = document.createElement('script'); s.src = src; s.async = true; document.head.appendChild(s);
      });
    }
    ['scroll', 'keydown', 'pointerdown', 'touchstart'].forEach(function (ev) {
      window.addEventListener(ev, loadThirdParty, { once: true, passive: true });
    });
    setTimeout(function () {   // 先等 5 秒，再等瀏覽器閒置（最多再等 2 秒）
      if ('requestIdleCallback' in window) { requestIdleCallback(loadThirdParty, { timeout: 2000 }); } else { loadThirdParty(); }
    }, 5000);
  })();
</script>
```

```tsx
// Next.js：next/script
import Script from 'next/script'
<Script src="https://static.hotjar.com/c/hotjar-XXXX.js?sv=6" strategy="lazyOnload" />
<Script id="fb-pixel" strategy="lazyOnload">{`/* fbq init */`}</Script>
```

**注意事項**：GA4 / GTM 可用 `afterInteractive`（Next.js 預設）而非 lazyOnload，以免漏掉跳出前的 page_view；廣告腳本**不要**延後到互動後（收入影響，詳見 09）。INP 的長任務多半來自這類腳本的初始化，延後載入是最有效的 INP 修法。

### 11.6 INP：把長任務切開

```js
// 長任務切分：在迴圈 / 重運算之間讓出主執行緒
async function processItems(items) {
  for (const item of items) {
    render(item);
    if ('scheduler' in window && 'yield' in scheduler) { await scheduler.yield(); }
    else { await new Promise(r => setTimeout(r, 0)); }
  }
}
// 事件處理器：先畫 UI 再做重活
button.addEventListener('click', () => {
  button.textContent = 'Loading…';                  // 立即回饋（下一個 paint 就會看到）
  setTimeout(() => heavyWork(), 0);                 // 重運算延到下一個 task
});
```

### 11.7 以 web-vitals 送 GA4（監測真實使用者）

```html
<script type="module">
  import { onLCP, onINP, onCLS } from 'https://unpkg.com/web-vitals@6/dist/web-vitals.attribution.js';
```

## 12. 安全標頭範本

**使用情境**：nginx `snippets/security-headers.conf`（Apache 版見第 5 節；Next.js 見 6.1；Cloudflare 可用 Transform Rules → Modify Response Header）。機制見 04 第 13 節。

```nginx
# /etc/nginx/snippets/security-headers.conf
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()" always;
add_header Cross-Origin-Opener-Policy "same-origin-allow-popups" always;   # 'same-origin' 會破壞部分 OAuth / 廣告彈窗
# CSP：先用 Report-Only 跑 2 週，確認廣告 / GTM / 字型 / 圖片 CDN 都沒被擋再切正式
# 注意：upgrade-insecure-requests 在 Report-Only 標頭中會被忽略，只在正式 Content-Security-Policy 生效（https://www.w3.org/TR/upgrade-insecure-requests/#delivery）
# ===== 正式版：strict CSP（nonce + 'strict-dynamic'）——有 AdSense / GAM 的站只能用這版 =====
# Google 官方（AdSense 說明 16283098、GPT CSP 指南，查閱 2026-11-03）「只支援 strict CSP（nonce + 'strict-dynamic'）」，
# 明言不支援網域白名單（廣告網域會隨時間變動、不公布清單）。Google 給的 script-src 原文如下（nonce 每次回應隨機產生，所有 <script> 含 adsbygoogle.js 都要帶 nonce）：
#   object-src 'none'; script-src 'nonce-{random}' 'unsafe-inline' 'unsafe-eval' 'strict-dynamic' https: http:; base-uri 'none'; report-uri https://your-report-collector.example.com/
# （來源：https://support.google.com/adsense/answer/16283098 、https://developers.google.com/publisher-tag/guides/content-security-policy ，查閱 2026-11-03）
# nginx 本身不會產生 nonce：由應用層（Next.js middleware / PHP）產生並輸出整條標頭最單純；純 nginx 可用 $request_id 當 nonce，
# 再用 sub_filter 把模板中每個 <script nonce="__CSP_NONCE__"> 的佔位字串換成同一個值（需 ngx_http_sub_module，且上游回應不可先 gzip）
add_header Content-Security-Policy-Report-Only "object-src 'none'; script-src 'nonce-$request_id' 'unsafe-inline' 'unsafe-eval' 'strict-dynamic' https: http:; base-uri 'none'; img-src 'self' data: https:; style-src 'self' 'unsafe-inline'; font-src 'self'; frame-src https:; connect-src 'self' https:; upgrade-insecure-requests; report-uri /csp-report" always;
# sub_filter_once off;
# sub_filter '__CSP_NONCE__' '$request_id';
#
# ===== 過渡 / 無廣告站用：網域白名單版（二擇一；要用時把下一行取消註解、並註解掉上面的 strict 版）=====
# 網域白名單**非 Google 官方支援**，有 AdSense / GAM 的站不要長期用——廣告可能無預警失效；只適合無廣告站或 nonce 輸出尚未完成前的過渡期，上線後必須持續監看 report-uri
# add_header Content-Security-Policy-Report-Only "default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval' https://pagead2.googlesyndication.com https://*.googlesyndication.com https://*.doubleclick.net https://www.googletagmanager.com https://www.google-analytics.com https://*.adtrafficquality.google https://fundingchoicesmessages.google.com https://*.google.com; img-src 'self' data: https:; style-src 'self' 'unsafe-inline'; font-src 'self'; frame-src https://*.googlesyndication.com https://*.doubleclick.net https://www.youtube-nocookie.com https://*.google.com; connect-src 'self' https://*.google-analytics.com https://*.analytics.google.com https://*.googletagmanager.com https://*.doubleclick.net https://*.googlesyndication.com https://*.adtrafficquality.google https://*.google.com; upgrade-insecure-requests; report-uri /csp-report" always;
```

**注意事項**：

- AdSense / GAM 的 CSP（2026-11-03 查證）：AdSense 說明〈Integrate the AdSense ad code with a Content Security Policy〉與 GPT〈Content Security Policy〉指南都**只支援 strict CSP**（`'nonce-{random}'` + `'strict-dynamic'`，並保留 `'unsafe-inline'` `'unsafe-eval'` `https: http:` 作為舊瀏覽器 fallback；`object-src 'none'; base-uri 'none'`），**不提供、也不支援網域白名單**。做法：Next.js 在 middleware 產生 nonce 並傳給 `next/script` 的 `nonce` 屬性；WordPress / PHP 在模板輸出 nonce；每個 `<script>`（含 `adsbygoogle.js` 與 `adsbygoogle.push` 的 inline）都要帶 nonce，漏一個廣告就不出。GAM 另需 `googletag.setConfig({ safeFrame: { forceSafeFrame: true } })`，否則同網域創意在 CSP 下可能失效。上面範本的網域清單只是沒有 nonce 時的妥協，不是官方清單。
- 上 CSP 後用 GSC URL 檢查「網頁資源」確認 Googlebot 沒有被擋到 JS / CSS。
- `X-Frame-Options` 與 CSP `frame-ancestors` 二擇一即可（後者優先）。

Cloudflare Pages `_headers` 範例（Astro 靜態站）：

```
/*
  Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
  X-Content-Type-Options: nosniff
  X-Frame-Options: SAMEORIGIN
  Referrer-Policy: strict-origin-when-cross-origin
/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

（部署前用 securityheaders.com 驗證標頭是否生效；`_headers` 檔一個拼字錯誤就會讓整條標頭失效且不會報錯。）

**注意事項**（Cloudflare 官方部落格 2026-07-01、2026-09-15 與 AI Crawl Control 文件，查閱 2026-11-03）：
- **Pay Per Crawl 仍為 closed beta**（文件 2026-07-28 更新：需透過 signup 表單或 Enterprise 業務申請）；2026-06-16 changelog 新增可依 URI pattern 停用與動態定價（`crawler-price` 標頭 / Worker）。
- **「新預設」有三份有日期的官方說法，不要混寫成單一「2026-09-15 起新預設」**：
  1. 2026-07-01 部落格與 bots changelog 預告：新網域自 2026-09-15 起，Training 與 Agent 類在「顯示廣告的頁面」封鎖、Search 允許（來源：https://blog.cloudflare.com/content-independence-day-ai-options/ 、https://developers.cloudflare.com/changelog/product/bots/ ，查閱 2026-11-03）。
  2. 2026-09-15 部落格對有廣告網域的「建議預設組合」：Search = Allow、Training = **Disallow（AI Training）**（不是 Block）、Agent = Block on pages with ads、Preference Sync = Enabled。Training 選 Block 會把 Googlebot / Bingbot 等混合用途爬蟲整個擋掉；「Block on pages with ads」也會套用到混合用途的訓練爬蟲；只有 Disallow（AI Training）會豁免混合用途爬蟲——它寫入 robots.txt 偏好，開 Preference Sync 時純訓練爬蟲會在邊緣被擋。Bing 支援 robots.txt 訓練退出的目標時程為 2027 年初（來源：https://blog.cloudflare.com/accountable-mixed-use-ai-crawlers/ ，查閱 2026-11-03）。
  3. **現行文件（最後更新 2026-11-02）明寫「For new domains, Search, Agents, and Training use Allow (do not block) by default.」**，沒有依網域是否有廣告而不同的預設；「Block on pages with ads」只是可選動作；Disallow 只有 Training 可選；Personal Agents 預設繼承 Agents 政策（來源：https://developers.cloudflare.com/bots/additional-configurations/block-ai-bots/ ，查閱 2026-11-03）。
  **結論：以 Cloudflare 現行文件為準——新網域三類預設 Allow，開站時務必親自檢查設定；要擋訓練又保留搜尋，用 Training = Disallow（AI Training）而非 Block；Agent 可選 Block on pages with ads。** 既有客戶的設定自動搬到新控制項，不需動作；舊的「Block AI Bots」開關已棄用。
- **關鍵陷阱**：新版的「Block」與「Block on pages with ads」**也會套用到混合用途爬蟲（Googlebot、Bingbot、Applebot）**——只想擋訓練、保留搜尋，一定要選 **Disallow AI Training**，不要選 Block（社群已有誤選 Block 導致 Google 去索引的案例）。
- 若希望 AI 搜尋引用（OAI-SearchBot、Claude-SearchBot 等）進來，到 AI Crawl Control 確認 Search 類為 Allow；2026-04-17 起另有「Redirects for AI Training」（Pro 以上：訓練爬蟲抓到有 canonical 指向他處的頁面時回 301）。

## 15. IndexNow 推送片段

**使用情境**：發布 / 更新 / 刪除內容時通知 Bing（Copilot）、Yandex、Naver、Seznam、Yep（Google 不參與，查閱 2026-11-03）。

1. 產生 key（8–128 字元英數與連字號），放在 `https://example.com/{key}.txt`，檔案內容就是 key。
2. 推送：

```ts
// lib/indexnow.ts（Next.js / Node；在發布 webhook 或 build 後呼叫）
const KEY = process.env.INDEXNOW_KEY!
const HOST = 'example.com'

export async function indexNow(urls: string[]) {
  for (let i = 0; i < urls.length; i += 10000) {           // 單次上限 10,000
    const res = await fetch('https://api.indexnow.org/indexnow', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json; charset=utf-8' },
      body: JSON.stringify({ host: HOST, key: KEY, keyLocation: `https://${HOST}/${KEY}.txt`, urlList: urls.slice(i, i + 10000) }),
    })
    if (!res.ok && res.status !== 202) console.error('IndexNow failed', res.status)
  }
}
```

```bash
# 單一 URL（curl）
curl "https://api.indexnow.org/indexnow?url=https%3A%2F%2Fexample.com%2Ftopic%2Fnew-post%2F&key=YOUR_KEY"
```

**注意事項**：200 / 202 只代表收到；不要重複提交未變更的 URL（會被忽略或限流 429）；WordPress 用 Rank Math（Instant Indexing）或 Bing 官方 IndexNow 外掛自動處理。
