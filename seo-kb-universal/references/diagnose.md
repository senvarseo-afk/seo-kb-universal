# diagnose：流量與索引問題診斷

目標：把使用者描述的症狀收斂成第 12 章的一個主狀況，給出診斷步驟、解法、預估恢復時間與證據等級，不先改站。

## 步驟

1. 先問或確認四件事（缺一就先問）：什麼時候開始、掉多少（GSC 點擊 / 曝光 / 平均排名三者各自變化）、哪些頁型或國家掉、最近改了什麼（改版、搬遷、大量發文、廣告調整）。
2. 定位：
   ```bash
   python3 "<SKILL_DIR>/scripts/kb_lookup.py" --symptom <症狀關鍵字>        # 00 §6 症狀表，得到「第一站」
   python3 "<SKILL_DIR>/scripts/kb_lookup.py" --section "12 <狀況編號>"      # 讀該狀況的八段
   ```
   症狀表查不到時，用 `kb_lookup.py --section "12 1"` 走流量驟降決策樹，或全文搜尋。
3. 先排除假驟降：追蹤壞掉（12 B4）、季節性（B3）、GSC 資料延遲（12 §12 (9)）、bot 流量灌水（2026 年多個「AI 吃掉點擊」案例細看是 bot 與 query mix 改變，12 §12 (11)）。
4. 對照更新時間線：`kb_lookup.py --section "07 3"`，看症狀起始日是否落在核心更新或 spam update 期間。
5. 流量驟降類一律請使用者填 `_templates/流量驟降診斷單.md`（複製到專案資料夾），診斷結論寫進去。
6. 輸出時把「立即」與「中期」解法分開，附預估恢復時間與證據等級；社群共識的部分要標示。

## 常見對應（快速表，仍以 00 §6 為準）

| 描述 | 第一站 |
|---|---|
| 核心更新後整站掉 | 12 B1、07 §7 |
| 已檢索 / 已發現但未編入索引 | 12 A1、A2 |
| 排名在、點擊掉、SERP 有 AI Overviews | 12 B6、08 §4.5、08 §8 |
| Discover 歸零 | 12 B7、20 §20.7 |
| 曝光高 CTR 低 | 12 C3、05 §1 |
| AdSense 無效流量 / 社群導流日警示 | 12 H2、H5、22 §5 |
| AdSense 申請被拒 | 12 H1、22 §6 P1–P6、P30 |
| 多語版本互搶 / hreflang 錯 | 12 I2、E5、10 §2 |
| 某國流量一夜歸零 | 12 I5、25 §6 |
| 放榜日 / 活動日主機掛 | 12 E13、04 §11 |
| 大量模板頁被判 thin | 12 J1、11 §6 |

## 輸出格式

```
## 診斷：<一句話主狀況>（12 <編號>，證據等級：…）
- 症狀對照：…
- 最可能原因（按機率）：1. … 2. …
- 要你提供 / 確認的資料：…（GSC 哪份報表）
- 立即做：…（章節）
- 中期做：…（章節）
- 預估恢復時間：…（有條件）
- 不要做：…（常見誤診，例如核心更新後急著 disavow）
```
